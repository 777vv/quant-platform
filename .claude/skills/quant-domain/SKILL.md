# 投研与数据口径常识（quant-domain）

> 这里是**结论性口径**，用于快速判断数字对不对；完整推导与实测证据在 `docs/02-技术文档.md` 的对应修订条目里。
> 改动任何口径前，先按"协作铁律"问用户。

## 1. 资产与收益（最常被问到的一组）

```
总资产   = 持仓市值 + 现金余额
现金余额 = Σ资金转入 − Σ资金转出 − 净投入
净投入   = Σ买入(含费) − Σ卖出净额 − Σ分红净额
累计收益 = 持仓市值 − 净投入
```
- KPI 上拆成「浮动盈亏 = 市值 − 摊薄成本」+「已实现收益」两项展示。
- **区间收益**（本月/本年）= 今日累计收益 − 区间起始日前最后一个数据日的累计收益；收益率分母取该基准日的**持仓市值**（不是净投入）。
- **收益曲线起点** = max(所选区间起点, 首笔流水日)——避免曲线拖出长零值尾巴；因此只买过一只近期买入的基金时，选"近 3 月/近 1 年/全部"会得到同一段。
- **资金划转不产生收益**：转入/转出只搬钱，不进任何收益口径。

⚠️ **待用户拍板的已知问题（别擅自改）**：
1. **分红重复计入**：持仓重算里分红既"冲减成本"又"计入已实现收益"，导致 KPI 累计收益比曲线口径（市值−净投入）**多算一次分红**（实测差 196.50 元 = 该笔分红金额）。两个候选口径：**A** 分红计入已实现、不冲减成本；**B** 冲减成本、不计入已实现。用户说"先不动，没想好"。
2. **移出自选的基金不计入净投入**（净投入只统计仍在自选池且有流水的基金），会造成现金余额与已实现盈亏的缺口；是否一并梳理也待用户确认。

## 2. 价格与复权（决定"历史数字准不准"）

- **场内 ETF**：库里存的是**前复权**日K（`fund_etf_kline.close`，fqt=1）。前复权把**历史价格压低**（等于把分红从价格里抹掉），**最新一日的前复权价才是真实成交价**。
- **场外基金**：库里存单位净值/累计净值/复权净值（`fund_nav`）；**单位净值本身就是未复权**，可直接当"真实价格"。
- **需要真实历史价格的口径**（历史股息率等）必须用 `fund_etf_kline.unadj_close`（未复权，fqt=0，由每日全量同步补齐）。缺失时的正确做法是**显示 `--` 并说明**，**不要用前复权价顶替**（会系统性高估）。
- 回测/信号计算统一用前复权（口径自洽）；涉及现金流与真实价格的记账口径才用未复权。

## 3. 股息率（V3.4）

- **单次分红股息率** = 每份分红 ÷ 除息日真实价格。
- **TTM 股息率** = 过去 12 个月每份分红合计 ÷ 当日真实价格；按除息日（进入窗口）与除息日 +12 个月（滚出窗口）**阶跃变化**。
- **当前时点**用前复权最新价即可（与真实价等值）——所以基金池列表的「股息率(TTM)」列当天就准；**历史段**才需要未复权价。
- 分红数据源：东财分红送配页（权益登记日/除息日/发放日/每 10 份派现金），与用户自录的分红流水按**日期合并**展示。

## 4. 指数估值

- 数据源：中证指数官网 `perf/index-perf`，字段 **`peg` 即市盈率 PE**（中证官网历史命名）。
- **只覆盖中证/上证系列指数**；深市指数、债券指数、海外指数没有该数据（页面按情况给不同提示，债券类指数不适用 PE）。
- 百分位是**自算**：近 10 年（不足 10 年取全历史）逐日 PE 中"PE ≤ 最新 PE"的交易日占比；≤20% 低估、20–80% 合理、≥80% 高估。
- 局限：只有 PE 没有 PB；绝对分位且窗口固定；收盘后才更新；分位档位只是映射，不构成买卖建议。

## 5. 持仓与记账规则

- **摊薄成本价** = 累计成本 ÷ 份额；卖出按摊薄成本结转已实现盈亏；分红处理见第 1 节待决项。
- **分红录入**：默认按现金分红（税前），只填金额（价/份额提交 0）；红利再投资拆成"分红 + 买入"两笔。
- **买卖录入**：只填**成交金额与成交数量**，成交价是只读派生值（金额 ÷ 数量，4 位小数）。
- **转出**不得超过现金余额（编辑历史流水时会把原记录排除再算）；**已持仓基金不得移出自选**（需先卖出全部份额）。
- 净值/份额类字段 2 位小数、价格 4 位小数；金额一律等宽数字展示。

## 6. 数据源与降级

- 东财 `push2`/`push2his` 存在**按路径的间歇封堵**（`http=000`），项目内置降级：看板读库内快照、迷你线与基准线有降级标记（10 分钟 TTL）、手动刷新可绕过降级窗口。
- **请求路径上禁止慢通道**（带域名退避的 K 线拉取只允许出现在后台同步任务里）。
- 抓取类数据（基金档案、分红、估值）都走"每日一次 + 手动同步强制"的节奏，**绝不在看图/看列表的请求里临时抓取**。

## 6.1 增量同步口径 ⚠️ 易错

- **"数据源给了当天一行" ≠ "这行已定稿"**：盘中那根 bar 是实时价，直到收盘才是终值；场外净值也可能当天晚些时候才发布。
- 因此**增量同步的下界绝不能越过当天**（`beg = min(游标 + 1 天, 今天)`）。写成"游标+1 天"就会出现：首轮写入当天那行后游标被推到当天 → 下一轮区间为空 → **当天数据永远停在第一次写入的那一刻**，手动同步也只会返回"无新数据"（V5.0 实测：515080 停在 09:30 的开盘价、成交量 70470）。本项目 ETF 与场外两条增量路径都已按此夹取。
- 排查"今天的数据不更新"这类反馈时，先看**库内当天那行的 `created_at`/成交量**（是不是只有开盘那一下），再看 `sync_log`（任务是否在跑、`record_count` 是否正常）——两者都"正常"却数据不动，基本就是游标越过当天。

## 6.2 新增一个策略的落地清单（三个策略已按此路径落地）

**配置是每支基金独享的**（`strategy_config` 唯一键 = 基金 + 策略类型），**代码逻辑按策略类型统一跑**（策略注册表按 `type()` 分发）。新增策略 = 新增一个 `@Component` 实现类，框架代码不动：

1. **策略类**（`com.quant.strategy.{网格 grid / 估值 valuation / 震荡 oscillation}`）：实现 `type()`、`name()`、`validateParams()`（中文报错）、`generateSignal()`（实盘）、`decide()`（回测）。
   - **实盘与回测必须共用同一个判定核心**（如震荡向上的 `judge()`），否则同一套口径会出现两份实现、迟早走散；差异只允许在"输入来源"：实盘取 `StrategyContext`（含 `currentShares` 实际持仓、`prevDirection`/`prevPrice` 前一次买卖信号），回测取 `BacktestState.getShares()` + `scratch`。
   - 需要"上次成交点位"这类状态时：回测存 `scratch`，实盘读 `signal_record`（**只认 BUY/SELL，HOLD 不是交易信号**）。
   - 仓位以"份数"为口径的策略实现 `validateBacktest(...)`：回测前校验本金买得起满仓份额（含 1% 费用缓冲），否则"满仓"买不满、档位规则失真。
   - 参数阈值一律走 `Strategy.dec/intOr/dblOr/strOr` 安全取值（Jackson3 对缺失节点会抛异常）。
2. **两处"窗口天数"分支**：`SignalServiceImpl.windowDays()`（实盘加载窗口，`loadRecent` 收**自然日**，按根数回看要 `×1.6+30` 换算）与 `BacktestServiceImpl.warmupDaysOf()`（回测预热）。
3. **前端**：`StrategyParamForm.vue` 加该类型的模板 + `defaults` 默认值；策略下拉由 `/strategies/types`（注册表）驱动，**自动出现、无需改菜单**。参数标签后带问号说明（悬浮），新用户不看文档也能填对。
4. **文档**：`docs/05` 手册加"6.x 某策略：每个参数的含义"（参数表 + 触发→档位表 + 注意事项）、`docs/02` 追加修订条目、`README` 策略行。

**口径示例（震荡向上，V5.4）**：上涨一律卖出、下跌一律买入；首次/二次只决定基准（首次＝窗口极值、二次＝上次成交点位），分支由**前一次信号方向**决定，起步按首次分支；档位在「底仓→满仓」区间插值（半仓＝底仓+1/2差、三分之二＝底仓+2/3差）；涨跌同触时**卖出优先**，但卖出算出"不动"时仍要评估下跌类（否则死锁）；**仓位无变化不出信号**。

## 7. 术语对照（避免歧义）

| 说法 | 本项目口径 |
| --- | --- |
| 净投入 | 真正投入到持仓里的钱（含费、扣掉卖出与分红回来部分） |
| 现金 | 账户里没买基金的钱 = 转入 − 转出 − 净投入 |
| 摊薄成本 | 累计买入成本扣除卖出结转与分红后的单位成本 |
| 已实现盈亏 | 卖出与分红带来的、已落袋的盈亏 |
| 浮动盈亏 | 当前市值 − 摊薄成本 |
| TTM | 滚动 12 个月（trailing twelve months） |
