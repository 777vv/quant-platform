## 仪表盘「总资产卡 → 收益日历」实现方案

### 一、口径（已按你的拍板确定）
- **日收益额** = 相邻两个「数据日」的**累计收益之差**（累计收益 = 当日持仓市值 − 净投入，即平台现有收益曲线的 `pnl`）。好处：日历里一个月内各日相加 = KPI 卡的月收益，能对账；资金转入/转出天然不进收益（符合"划转不产生收益"）。
- **日收益率** = 日收益额 ÷ **前一数据日的持仓市值**（与现有 KPI「月/年收益率」同分母口径；基准日市值为 0 或没有前一数据日时该格显示 `--`）。
- 与 KPI 卡「当日盈亏」口径不同（那个只看价格波动、不扣资金流）——日历弹框底部用一行小字写明本口径。
- 已知口径边界：**移出自选池的历史基金不计入**（平台既有口径），弹框底部一并说明。

### 二、后端（1 个新接口 + 1 个 DTO，复用现有计算）
1. **`GET /api/dashboard/profit/calendar?year=2026`** → `ProfitCalendarVO`：
   - `year`、`hasData`；
   - `days[]`：`{date, pnl(元), pct(%), marketValue}`（只含有效数据日，非交易日/无数据日不下发，前端按日期对格子填）；
   - `months[]`：`{month:'2026-01', pnl, pct, dayCount}`（自然月汇总，服务端聚合，保证与 KPI 一致）；
   - `yearPnl` / `yearPct` / `yearDayCount`（全年汇总）。
2. 实现：`ProfitStatsService.calendar(int year)` → 复用现有私有 `computeSeries(区间起点, tradedFunds)`——起点取 **year-01-01 往前多取 3 个月**（沿用 `FIRST_PERIOD_LOOKBACK_MONTHS`，保证该年第一个数据日有"前一数据日市值"作分母），算完裁剪到该年；**跳过 benchmark（沪深300）整条外部依赖**——历史 76 秒卡死就出在这条链路上，日历用不到它，跳过即省掉最大风险项。
3. **服务端缓存**：按年份的内存缓存（`volatile` Map<年份, 结果+加载时间>，TTL 10 分钟，与现有 `summary()` 的 30 秒备忘同款做法）；数据只在同步/记账后变化，10 分钟内视为新鲜。
4. 文件：`DashboardController`（+1 映射）、`ProfitStatsService`/`ProfitStatsServiceImpl`（+calendar 方法、抽出可复用的裁剪小函数）、新增 DTO `ProfitCalendarVO`。

### 三、前端（1 个新组件 + 3 处小改）
1. **`DashboardView.vue`**：
   - 删掉总资产卡上的「转入/转出」按钮（`openEntry` 仍被新手引导第 2/3 步使用，不会变死代码）；
   - 卡片加 `cursor: pointer` + 悬停反馈（主卡原本被显式重置了悬停动效，本次给它一个"可点"的阴影变化）、`@click="openCalendar"`；
   - 挂载新组件 `<ProfitCalendarDialog v-model="calendarVisible" />`；**`onMounted` 一行不改**（不预取任何日历数据）。
2. **新组件 `web/src/components/dashboard/ProfitCalendarDialog.vue`**（沿用项目 `:model-value` + emit 的弹框封装习惯，`@open` 时才加载）：
   - 顶部工具条：**视图切换（月 / 年）** · **指标切换（收益额 / 收益率）** · 导航（月视图 `‹ 2026-08 ›`；年视图 `‹ 2026 ›`）；
   - **月视图**：7 列网格（周一~周日），每格 = 日号 + 收益值（按指标切换：`+1,240` 元 或 `+1.2%`），正红负绿（涨跌 token）、非交易日/无数据日灰显、今天有高亮；没前值那天显示 `--`；
   - **年视图**：**12 个小月历块**（格子只染色表强弱、不写数字），每块下方标当月汇总（金额或收益率）与交易日数；**点某个月直接切到该月的月视图**；
   - 底部汇总 + 口径说明（一句话：日收益=相邻数据日累计收益差、收益率分母=前一数据日持仓市值、移出自选的历史基金不计入）；
   - 加载中显示骨架/加载态，失败给重试按钮。
3. **`web/src/api/dashboard.ts`**：加 `profitCalendar(year)`；**模块级按年缓存（TTL 10 分钟，与 `fundOptions` 同款写法）**。

### 四、性能（你的重点）
| 场景 | 请求行为 |
| --- | --- |
| 刷新/进入仪表盘 | **零新增请求**（不预取、不加到 onMounted） |
| 首次点开卡片 | 1 次请求（默认当前年，约 250 行，跳过 benchmark） |
| 同年切月 / 切指标 | **零请求**（该年数据已在内存） |
| 切到往年年份 | 1 次请求（只取那一年；前后端各一层缓存，10 分钟内再切回来零请求） |
| 关闭再打开弹框 | 缓存命中零请求（超 10 分钟才重取） |
