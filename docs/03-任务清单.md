## 使用说明

- **状态标记**：`⬜` 未开始 → `🚧` 进行中 → `✅` 完成（完成后可在单元格内追加日期，如 `✅ 09-20`）；`⏸` 搁置需注明原因；
- **实现顺序**：任务按依赖关系排列，原则上按编号顺序执行；同里程碑内无依赖标注的任务可并行；
- **完成标准（DoD）**：代码提交 + 本任务"验收依据"通过 + 如涉及外部接口完成对应 ⚠️ 验证项；
- **验收依据**：`FRxx` 指需求文档对应功能节的验收标准；`技术文档 x.x` 指对应设计章节；
- **⚠️ 前置验证**：带 ⚠️ 的任务内含技术文档第 15 节所列的实测验证项，验证结论需回写到任务备注。

> **M4 备注（⚠️ 实测结论）**：
> 1. **push2/push2his 间歇性 TLS 连接失败**：`HTTP/1.1 header parser received no bytes`，HTTP/2 与 HTTP/1.1 双版本均复现，同一时刻 curl 亦 exit 35，判定为链路侧（本机网络到东财）问题而非客户端指纹。代码以「重试 3 次 + 行情降级返回库内快照 + 基准/迷你线降级为空」应对，链路恢复后自动补齐，不影响主流程与页面可用性。
> 2. 因上述链路问题，sparkline 的**真实拉取**在冒烟时段无法端到端跑通，改以预置同构缓存验证接口契约（30 点原样返回，首末日期正确）；行情恢复后由 5 分钟任务自动填充真实数据。

> **M5 备注（实测结论与偏差）**：
> 1. **提示词经三轮实测加固**（均为真实对话复现的问题）：① 初版越界拒答过弱（写诗直接照做）→ 加统一话术与"包装无效"原则；② **工具优先未落实**：问"跟踪什么指数/估值贵不贵"时未调工具、凭记忆编造（实测编出"上证50指数、PE 10.78"，库内实为"沪深300指数、PE 13.36"）→ 加"先调工具后开口"硬约束 + 工具描述补"何时必须调用"，修复后日志确认工具被真实调用、数字逐字一致；③ 抗泄漏：注入下曾复述提示词、翻译规则攻击曾泄漏全文 → 收紧措辞并加 `PromptGuard` 确定性拦截。**采样温度 0.6 → 0.3**（事实查询场景抗发散）。
> 2. 模型 `glm-4-flash` 为免费档，指令遵循能力有限：在"复合注入"（忽略指令+要提示词+写诗）下提示词层仍会退让，故由 `PromptGuard` 在入口拦下。**若希望更稳的边界表现，可换 `glm-4-air`/`glm-4-plus`**（涉及费用，待确认）。
> 3. Spring AI 2.0.1 实测：`ToolCallingAdvisor` 在流式下把工具调用帧内部消化、不向外透出（其 Builder 无透传开关），故 `event:tool` 帧实际不会产生；前端改为"等待首个 token 期间显示『正在查询数据…』"的等效过程提示（协议保留 tool 帧处理，未来版本透出即自动生效）。此为与 6.8 原设计的偏差，已记录。
> 4. 邮件通知已开启并实测：`POST /api/notify/mail/digest`（新增补发入口）真实发出摘要邮件（纳入 1 条买入信号），**幂等复点返回 0 不重发**（`notified_flag` 回写生效）。
