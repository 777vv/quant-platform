# 个人量化投资助手 · 使用手册

> 本手册讲**这个平台怎么用**：每个功能做什么、在哪里点、参数是什么意思、有哪些注意事项、出错怎么办。
> 应用内可在侧栏【使用手册】阅读；AI 助手也读同一份手册，所以"这个功能怎么用"直接问 AI 也行（问它比翻这里更快）。
> 手册只讲"怎么用"；每个功能为什么这么设计、口径的取舍，见 `docs/02-技术文档.md`。

## 1. 快速上手

### 1.1 这是什么平台（一句话与三条边界）
这是一个**给自己用的指数基金投资助手**：管住自选池、算清持仓与收益、按策略给买卖建议、每天早上告诉你该看什么，并提供回测验证。

三条边界先记住，能省很多困惑：
1. **只给建议，不自动交易**——平台不会替你下单，所有买卖都由你在券商 App 自己操作。
2. **只支持指数基金**：场内 ETF 与场外指数基金；不支持个股、不支持期货外汇、不支持主动管理型基金。
3. **数据来自东方财富公开接口**，只覆盖"你自选池里的基金"，没导入的基金查不到行情。

### 1.2 第一次使用的四步
1. **登录**：打开 `http://localhost:5173`，用管理员账号登录（默认 `admin` / `admin123`，登录后请到【平台配置 → 安全设置】改密码）。
2. **导入一只基金**：【数据导入】→ 输入 6 位代码（如 `510300`）→ 点【校验】→ 确认类型是"场内ETF/场外指数基金"→ 点【开始导入】→ 等进度条走到完成（一只基金约 10~60 秒，ETF 会写入 2000+ 条日 K）。
   - 导入是**整段覆盖**：同一只基金重复导入，日K/净值/分红/指数估值全部按数据源最新值重写（V5.26 起分红与未复权收盘价也纳入导入，股息率与除息点位 q 标记导入即可见）。
   - 跟踪指数的估值若数据源没有（部分债券/商品指数无 PE），进度会提示"暂不可用"，不影响行情数据导入。
3. **记一笔持仓**（可选）：【基金池】→ 点基金名字进详情 → 【交易流水】页签 → 新增买入（**只填成交金额与数量**，价格自动算）。
4. **看今日结论**：【仪表盘】看总资产与当日盈亏；【AI用量统计】旁边的 AI 浮窗（右下角圆形按钮）可以直接问"我现在持仓怎么样""最近有什么买卖信号"。

### 1.3 数据从哪来、什么时候更新
- 行情/净值/估值全部来自**东方财富公开接口**，每天由定时任务自动同步（时间表见第 12 章）。
- 你导入或同步后，数据存在本地 MySQL 里；页面读的是本地库，不实时请求上游，所以**断网也能看历史**。
- 判断数据新不新：看【基金池】的「最后同步」列。

## 2. 数据导入

### 2.1 支持什么、不支持什么
| 项目 | 说明 |
| --- | --- |
| 支持 | **指数型基金**：场内 ETF（如 510300）、场外指数基金（如 110003） |
| 不支持 | 股票型/混合型/债券型等主动基金、个股、期货外汇、货币基金 |
| 数据范围 | 近 15 年；成立不足 15 年的自成立日起 |
| 导入内容 | 场内：前复权日 K（开高低收、成交量额）；场外：单位净值 + 复权净值；另外同步该基金**跟踪指数**的历史估值（PE） |

不支持的品种在校验阶段就会被拦下，并给出具体原因（例如"非指数型基金（类型：混合型-灵活），平台仅支持指数基金"）。

### 2.2 导入步骤与校验结果的三种状态
1. 【数据导入】输入 6 位代码 → 点【校验】。校验会去上游确认这只基金存在、类型合格、并识别它的跟踪指数。
2. 看「池内状态」标签，**三种状态对应三种含义**：
   | 状态 | 含义 | 按钮 | 点下去会发生什么 |
   | --- | --- | --- | --- |
   | **新基金** | 从没导入过 | 【开始导入】 | 全量拉取历史数据并加入自选池 |
   | **已在自选池** | 已导入且在池里 | 【重新导入（覆盖刷新）】 | 整段重拉历史数据并覆盖本地，不会产生重复 |
   | **已移出自选（历史数据保留）** | 导入过、后来被你移出自选 | 【恢复到自选池并导入】 | 重新放回自选池，并覆盖刷新历史数据 |
3. 点按钮后进度条会显示阶段（拉取日K/计算复权净值/写入/同步估值），完成后可到【基金池】看到它。

### 2.3 导入是"整段覆盖刷新"，不是只补缺的几天
这是最容易误解的一点：**历史导入会从成立日（或近 15 年）整段重新拉取，然后覆盖本地数据**，而不是只补最新几天。原因是**前复权价会随每次分红除权整体变化**——只追加会让新旧数据口径不一致（详见第 12.3 节）。
- 只想补最新几天：用【基金池】或详情页的**同步**按钮（那是增量 upsert）。
- 覆盖刷新不会产生重复行（先删后插 + 唯一键兜底），可以放心重复点。

### 2.4 导入失败怎么办
- 进度条会显示失败阶段与原因；常见原因是上游接口抖动或限频（返回空数据/超时）。
- 处理：等 1~2 分钟重试即可；反复失败先确认网络能否访问东方财富，再看后台日志 `logs/`（关键词"历史导入失败"）。
- 导入中断不会污染已有数据（写入是事务化的：要么整段替换成功，要么保持原样）。

### 2.5 批量导入（一次导入多只基金）
- **在哪里**：【数据导入】页第二张卡「批量导入」。两种给清单的方式，可任选或组合：
  - **候选筛选**：填"规模 ≥ N 亿、上市 ≥ N 年"（默认 10 亿 / 6 年），点【查询符合条件的 ETF】，在表格里勾选（已在池中的行不可勾选）；
  - **代码清单**：把代码粘贴进文本框，换行/逗号/空格分隔都行，自动提取 6 位数字。
- **发起**：点【开始批量导入（N 只）】。导入是**串行**的（每只间隔 0.5 秒），因为数据源（东财）会按路径间歇封堵，并发只会更快被封；100 只顺利约 10~20 分钟，可离开页面，回来进度还在（保留 2 小时）。
- **封堵窗口自动暂停**：连续 3 只失败时判定进入封堵窗口，任务自动暂停 90 秒再继续（期间显示"疑似数据源封堵窗口"），不用人工盯着。
- **失败清单**：单只失败不会中断批量；结束后失败清单列出代码与原因（如"非指数型基金"），点【重试失败项】只重跑失败的。
- **与定时任务的关系**：批量导入期间持有数据同步的互斥锁——15:30 ETF 全量、20:00 净值、20:30 估值、盘中 5 分钟同步会自动跳过并留日志；锁被占用时批量会先等待约 1 分钟再提示。
- **注意**：单批上限 200 只；批量导入的基金入池后，每日定时同步会自动覆盖它们（见 12.1 时间表），数据量与任务时长会随池子变大而增长。

## 3. 基金池

### 3.1 自选池是什么
自选池 = 你**导入过且没有移出**的基金集合。平台的行情同步、策略信号、AI 查询都只覆盖自选池内的基金——所以"查不到某只基金的行情"通常是因为它不在自选池。

### 3.2 列表每一列怎么读
| 列 | 含义 / 口径 |
| --- | --- |
| 代码 / 名称 | 名称后带小标签表示**持仓中** |
| 跟踪指数 | 该基金跟踪的指数（如 沪深300指数 000300），估值百分位用它关联 |
| 标签 | 你自定义的分类（红利/宽基/债券…），可筛选 |
| 最新价/净值 | ETF 是前复权收盘价，场外是单位净值（数据日期看「最后同步」） |
| 涨跌幅% | 相对前一交易日的涨跌 |
| 规模(亿) | 净资产规模，来自基金档案（季末披露，注意截止日） |
| 溢价率 | 仅场内 ETF 有意义：= (收盘价 − 当日净值) / 净值；正数表示场内买贵了 |
| 运作费率 | 管理费/托管费(+销售服务费) 合计（%/年） |
| 股息率(TTM) | 过去 12 个月每份分红合计 ÷ 当日真实价格（口径见 4.4） |
| 估值百分位% | 跟踪指数 PE 在近 N 年中的分位（越低越便宜），无估值数据显示 `--` |
| 已配策略 | 该基金是否已配置策略（有/无） |
| 最后同步 | 本地最新数据日期；滞后会在仪表盘标红 |

### 3.3 标签、筛选与分页
- 在【基金池】上方可**关键词搜索**（代码或名称）、按**标签**筛选，都是服务端筛选（作用于全部数据，不是只筛当前页）。
- 支持跨页勾选后批量操作；分页每页可选 10/20/50/100 条（默认 10 条/页）。
- 标签库在【基金池 → 管理标签】里维护（预定义 + 自定义），给基金打标签在列表的标签列点开编辑。

### 3.4 移出自选（软删）与恢复
- **移出自选 = 软删**：基金不再出现在列表与同步范围里，但**历史数据（日K/净值/估值/流水）全部保留**，标签关联也保留。
- **持仓中的基金不允许移出**：必须先卖出全部份额（防止持仓失去行情来源）。已清仓但有历史流水的可以移出。
- **想恢复**：到【数据导入】输入代码 → 校验会显示「已移出自选（历史数据保留）」→ 点【恢复到自选池并导入】。恢复后它又会回到自选池并参与每日同步。
- 注意（已知口径限制）：净投入只统计**当前仍在自选池**的基金，所以把已清仓基金移出自选后，它的历史买卖不再计入净投入，现金余额与已实现盈亏会出现缺口。若你经常这样做，先看第 13.2 节。

## 4. 基金详情

### 4.1 页签总览
进入基金详情（点基金名）后是六个页签：**行情走势 / 指数估值 / 交易流水 / 策略配置 / 回测**，以及顶部的档案区（规模、费率、溢价率、最后同步等）。
档案类字段（规模/费率/跟踪指数）**每天刷新一次**，可在详情页手动强制刷新；溢价率每次同步时自动算。

### 4.2 行情走势图怎么用
- **区间选择**：右上角下拉（近3个月/1年/3年/5年/10年），或直接选**自定义日期区间**（两者互斥，选自定义后下拉失效）。
- **框选**：在图上按住拖动即框选一段，日期区间会自动回填并重新加载（图表已内置框选工具，不必点工具箱图标）。
- **技术指标**：副图可切换成交量、MACD；主图可叠加 MA、BOLL（指标会**往前多取 150 天预热**，所以窗口开头的指标不会失真或空缺）。
- **图表高度**：副图开关变化时画布高度与网格自动重排。

### 4.3 图上的 b / s / q 标记是什么意思
- `b` = 买入、`s` = 卖出：取你在本平台记录的**交易流水**；
- `q` = 分红除息：取东方财富的分红送配记录（**全部除息日**，不只你持有的部分）。
- 标记是按图上可见窗口自动裁剪的散点，不参与悬停提示（避免用价格污染 tooltip）；图上有一条说明文字。

### 4.4 股息率副图与两个股息率口径
- **单次分红股息率** = 每份分红 ÷ 除息日真实价格；
- **TTM 股息率** = 过去 12 个月每份分红合计 ÷ 当日真实价格（红利类指数/基金报"股息率"时通常用这个口径，平台默认展示它）；
- 分母用的是**未复权真实价格**：本平台 ETF 存的是前复权价，它把历史价格压低了，直接当分母会系统性高估历史股息率，所以专门存了未复权收盘价。
- 副图 = 紫色阶梯线（TTM 股息率）+ 蓝色散点（每次分红），独立百分比轴；无分红的基金副图为空。

### 4.5 「区间表现」表的口径
区间表现（交易日/区间涨跌幅/最大回撤/年化波动率）的口径是**图上当前可见的那一段**（所见即所测）：缩放或框选后自动重算，并且**不重新请求接口**（用已加载序列本地计算）。所以"表里的数字"和"图上看到的范围"始终一致。

### 4.6 指数估值页签
展示该基金跟踪指数的 PE 历史与百分位（数据来自中证指数等公开源，与"估值百分位"列同源）。跟踪指数未识别或缺失时，会明确提示"未识别跟踪指数"，而不是给一个错的图。

## 5. 记账与持仓

### 5.1 五种交易类型
| 类型 | 需要填 | 说明 |
| --- | --- | --- |
| 买入 | 基金、日期、**成交金额 + 成交数量**、手续费(可 0) | 价格自动算 |
| 卖出 | 同上 | 按摊薄成本结转已实现盈亏 |
| 分红 | 基金、日期、**金额**（默认现金分红，税前） | 计入已实现收益并冲减成本 |
| 转入 | 日期、金额（不关联基金） | 账户级资金划入，现金增加 |
| 转出 | 日期、金额（不关联基金） | 账户级资金划出，**不能超过现金余额** |

### 5.2 买入/卖出：只填金额和数量，价格是算出来的
- 成交价字段是**只读**的，等于 `成交金额 ÷ 成交数量`，保留 4 位小数。
- 为什么这样设计：对账单上的**金额**最准（含各种费用尾差），手填价×量常与实际扣款对不上。
- 保存前会显示**实时预估**（持有份额、成本价、现金、已实现盈亏的变化），可以先看一眼再保存。

### 5.3 分红怎么记（含红利再投资）
- 默认按**现金分红（税前）**处理：只填金额，价格/份额提交 0，分红计入已实现收益并冲减持仓成本。
- **红利再投资**请拆成两笔：先记「分红」（金额），再记「买入」（金额=分红額、数量=新增份额）。这样两件事都能单独追溯。
- 场外基金的分红也可能体现在净值里（累计净值口径），本平台的分红记录以东方财富的分红送配数据为准（图上的 `q` 标记）。

### 5.4 现金与收益怎么算（三个公式）
```
净投入   = Σ买入(含手续费) − Σ卖出净额 − Σ分红净额
现金余额 = (Σ转入 − Σ转出) − 净投入
总资产   = 持仓市值 + 现金余额
```
- 所有口径都由**一个服务**统一算出（前端只展示），所以页面之间不会打架。
- **累计收益 = 总资产 − 净投入**（即把"外部转进来的钱"排除后的真实盈亏）。
- 转出额度上限 = 现金余额（现金为负时不允许任何转出）。

### 5.5 持仓、成本与盈亏怎么算
- 持仓由**交易流水自动重算**（不是手工维护的表）：份额加减、成本摊薄。
- **摊薄成本价** = 剩余持仓成本 ÷ 持有份额；买入会把手续费计入成本，卖出按摊薄成本结转。
- **已实现盈亏** = 卖出金额 − 手续费 − 卖出份额 × 成本价（分红也计入已实现）。
- **浮动盈亏** = (最新价 − 成本价) × 份额；**当日盈亏** = (最新价 − 前一日价) × 份额。

### 5.6 编辑与删除流水的规则
- 流水可编辑/删除，改完持仓与收益会立即重算；删除末页最后一条会自动回退一页。
- 编辑成"转出"时会重新校验额度上限（会排除原记录自身，避免把自己挡住）。
- 建议：只改错别字/金额；如果只是记错基金，删除后重记更干净。

## 6. 策略配置与买卖信号

### 6.1 策略在哪里配、启用是怎么生效的

- **备注（V5.34）**：新增策略时可以填一段备注（如建仓思路、调参缘由），列表里有备注列；
- **修改已配置的策略**：列表里的「编辑」按钮 = 打开与新增相同的表单（预填当前类型/参数/备注），改完保存即生效。
  编辑时**策略类型不可改**（换类型等于换策略，请删除后重建）；备注留空保存不会清掉已存的备注。
- 列表里**不再显示参数摘要**（V5.36）：点「编辑」即可查看并修改全部参数。
- **持仓基金列表**（基金池 → 持仓基金）：按**市值从大到小**排序、每页 10 条分页；**基金名称可点击**进详情。全部卖出后该基金仍会留在列表里（份额 0、市值 0、已实现盈亏保留），作为投资历史。
- 位置：基金详情 → **策略配置**页签 → 新增/编辑。同一只基金每种策略只能配一套（唯一键：基金+策略类型）。
- **启用（enabled）**：只有启用的策略才参与每个交易日 09:00 的信号计算与邮件；停用后仍可用来回测。
- 参数以 JSON 存在库里，保存时会**立即校验**（范围不对直接报错，不会存进去）。每个参数后面有个**问号**，鼠标悬浮即可看到该参数的含义与取值范围。
- 目前四个策略：**金字塔网格**（越跌买越多的网格，见 6.2）、**倒金字塔网格**（越跌买越少的网格，见 6.3）、**震荡向上**（涨了卖跌了买，见 6.4）、**红利网格**（低波动慢牛品种的密网格，见 6.5）、**纳指网格**（高波动跨境品种的宽网格 + 溢价/趋势闸门，见 6.6）。每支基金各自的配置互不影响，但代码逻辑按策略类型统一执行。
- **四个网格策略是同一套规则的不同预设**：格线固定不漂移、以「最近一次实际成交价」为格位参考、一天跳空穿几格就买卖几格、底仓/满仓夹取，外加四道**买入闸门**（趋势均线 / 溢价率 / 回测假设溢价 / 估值 PE）。差别在默认值与份额阶梯：红利＝等差密格+高底仓+保留底仓；纳指＝等比宽格+低底仓+区间上移+MA60/溢价闸门；金字塔＝每格递增（越跌买越多）；倒金字塔＝每格递减（越跌买越少）。**所有阈值都能自己改**。
- ⚠️ **V5.28 起【网格交易 GRID】与【估值百分位 VAL_PERCENTILE】已从平台移除**（不再可选、不可回测）：它们的历史回测记录与旧配置仍保留可见（列表里标注「已下线」），需要清理的话在【策略配置】里删除对应行。

### 6.2 金字塔网格策略（PYRAMID_GRID）：每个参数的含义

策略逻辑：**跌得越深，每一格买得越多**（形状像正金字塔，底部宽）。格线由下沿/上沿/格数一次算出、固定不漂移；价格每下穿一格按该格的份额买入、每上穿一格按该格的份额卖出，跨几格就成交几格；买入后的持仓受**满仓份额**约束、卖出不低于**底仓份额**。

份额阶梯：某格的成交份额＝`每格份额 + 每格增减 ×（格数 − 该格格位）`（卖出镜像：越靠上沿卖得越多）。所以「每格增减」填正数就是金字塔；**填 0 等于普通等量网格**。

| 参数（界面名） | 字段 | 含义 | 建议 / 界面默认 |
| --- | --- | --- | --- |
| 网格模式 | `mode` | 等差（每格价差固定）或等比（每格比例固定） | 低波动品种用等差，默认等差 |
| 网格下沿 / 上沿 | `lower` / `upper` | 网格区间的下界与上界价格（格线两端） | 对着近 1~2 年实际波动区间设，默认 1.40 / 1.62 |
| 格数 | `grids` | 上下沿切几格（2~200） | 单格幅度建议 ≥ 2 倍日均波动，默认 11 |
| 每格单位 | `perGridMode` | 按份额 / 按金额（价格越低自动买到越多份） | 默认按份额 |
| 每格份额 | `sharePerGrid` | **上沿那一格**的基准份额；往下按阶梯递增 | 默认 500 |
| 每格增减 | `pyramidStep` | 每深一格的份额增减；**正数=越跌买越多（金字塔）** | 默认 +250（500/750/1000…） |
| 底仓份额 | `baseShare` | 卖出下限：建议卖出后不低于它 | 默认 5000 |
| 满仓份额 | `fullShare` | 买入上限：建议买入后不超过它（防单边下跌打光子弹） | 默认 30000 |
| 初始仓位份额 | `initialShare` | 仅回测首日建仓；⚠️ 要大于底仓，否则网格只买不卖 | 默认 8000 |
| 涨破上沿 | `breakoutMode` | 区间上移 / 保留底仓不动 / 清到只剩底仓 | 默认保留底仓（慢牛品种） |
| 跌破下沿 | `breakdownMode` | 买 1 格后观望 / 区间下方继续按格买入 | 默认买 1 格后观望 |
| 单根最多成交格数 | `maxGridsPerBar` | 一根 K 线最多按几格成交（防极端跳空） | 0=不限 |
| 四道买入闸门 | `trendMaDays` / `premiumBuyMaxPct` / `backtestPremiumPct` / `peBuyMax`+`peBuyMin`+`peBoostMultiplier` | 趋势均线、溢价率、估值 PE——任一拦截即不出买入建议；卖出不受限 | 详见 6.5/6.6 的说明 |

⚠️ **风险**：金字塔在**单边下跌**里会迅速把仓位买重（越跌越买），务必设好满仓上限；它适合"跌下去能回来"的品种（红利、宽基指数），不适合个股或长期走弱的品种。

### 6.3 倒金字塔网格策略（INV_PYRAMID_GRID）：每个参数的含义

策略逻辑：与金字塔**方向相反**——**浅回撤接得多、跌得越深买得越少**（顶部宽、底部窄）。规则、参数、闸门与 6.2 完全一样，唯一的差别是「每格增减」为**负数**。

| 参数（界面名） | 字段 | 差别点 | 建议 / 界面默认 |
| --- | --- | --- | --- |
| 每格增减 | `pyramidStep` | **负数**＝越跌买越少（卖出镜像：越高卖越少，留住筹码） | 默认 −100（1500/1400/1300…） |
| 其余参数 | — | 同 6.2 | 默认取向偏趋势品种：等比、涨破上沿区间上移、MA60 与溢价 3% 闸门 |

设计意图：把子弹优先留给"浅回调"、深跌时保持克制。适合长期趋势向上但**深跌难以判断底**的品种（纳指这类跨境指数）。
⚠️ **风险**：仓位重心在上方（浅回调买得多），若价格一路阴跌不反弹，会先重后轻地套在上方；务必设满仓上限并用趋势闸门约束。

### 6.4 震荡向上策略（OSC_UP）：每个参数的含义
策略逻辑（V5.13 重构）：**跌了加仓、涨了减仓**，用「固定份额」在一个区间里来回做——不再有"首次/二次"之分，也不再按仓位档位定目标。

**对比区间**：从「K线天数那根 K 线」或「上次**实际交易**那根 K 线」中**更靠近今天**的一根开始，到今天为止。

| 参数（界面名） | 字段 | 含义 | 取值范围 / 界面默认 |
| --- | --- | --- | --- |
| 初始仓位份额 | `initialShare` | **仅回测首日生效**：开始回测时先按它买入建仓，从"已持有仓位"起步而不是 0 仓；填 0 不建仓 | 0 ~ 满仓，默认 10000 |
| 底仓份额 | `baseShare` | **卖出下限**：建议卖出后持仓不低于它；同时**买入后若不足此数，会直接建到该数** | ≥0，默认 5000 |
| 满仓份额 | `fullShare` | **买入上限**：建议买入后持仓不超过它。要与可用资金匹配，回测时本金必须买得起 | >底仓，默认 20000 |
| K线天数 | `windowDays` | 向前回看的根数，也是对比区间的**封顶**（取"K线天数那根"与"上次实际交易那根"中更近的一根） | 2~500，默认 60 |
| 上涨减仓% | `riseReducePct` | 现价较区间**最低点**上涨超过它 → 卖出「卖出份额」份 | 0~100，默认 5 |
| 下跌加仓% | `fallAddPct` | 现价较区间**最高点**下跌超过它 → 买入「买入份额」份 | 0~100，默认 5 |
| 买入份额 | `buyShare` | 每次加仓的**固定份额** | ≥1，默认 5000 |
| 卖出份额 | `sellShare` | 每次减仓的**固定份额** | ≥1，默认 5000 |
| 每档份额增减% | `sizingStepPct` | **分档功能（V5.29）：0＝关闭**（买卖都用固定份额，与历史行为一致）；正数＝越跌买越多、越涨卖越多（金字塔式）；负数＝越跌买越少、越涨卖越少（倒金字塔式）。第 n 档份额 = 固定份额 × [1 + (n−1)×此值]，n = 触发幅度 ÷ 阈值；倍数夹在 0.1 ~ 单笔最大倍数之间 | 默认 0（关闭） |
| 档位基准 | `sizingBase` | 档位从哪个区间算幅度。**锚点窗口（默认）**：跟着「上次实际交易」走、每次成交后档位重新起算，与触发口径完全一致——实测渐进下跌里档位基本停在第 1 档（结果与关闭分档逐笔相同）；**K线窗口**：按近 K线天数 根算、不随成交重置，渐进下跌会累加到第 2、3 档，放大效应明显（代价是与「锚点=实际成交」的口径不一致） | 默认锚点窗口 |
| 单笔最大倍数 | `maxSizingMultiple` | 深档时的倍数上限（默认 3），防止「越跌越多」在深跌里把单笔买到过大；份额最终仍受满仓上限夹取 | 1~10，默认 3 |

> **分档怎么用（一句话）**：想要"越跌买越多"的**真实放大效果**，请把「档位基准」切到 **K线窗口**——按默认的锚点窗口口径，档位会随每笔成交重置，
> 实测结果与关闭分档逐笔相同（515080 近一年：两者都是 11 笔、买入均值 5833 份、末资产 61785；切到 K线窗口后买入均值 6250 份、出现第 2 档 ×1.5 的 7500 份买入）。
> 两项都是可调参数，改下拉即可、不必改代码。建议说明里会写明档位与倍数，例如「分档：跌幅 13.79% 属第 2 档，份额 ×1.5（档位基准 K线窗口）」，便于对着成交明细核对。

四条执行规则：

1. **夹取**：买入不超过满仓、且买入后不足底仓时按底仓建仓；卖出不低于底仓——所以每次实际买卖的份额可能小于配置的份额（说明里会写明）。
2. **同时满足**：同一根 K 线两个阈值都满足时**买入优先**；买入算不出份额（已满仓）时才看卖出。
3. **无变化不出信号**：夹取后可交易份额为 0（已满仓 / 已到底仓）就不产生买卖信号。
4. **2 个交易日冷却 + 信号不落地不算数**（V5.16 由 5 改 2）：距上次**实际交易**不足 2 个交易日时只记 HOLD、不发邮件；发了信号但交易流水里没照做时该信号不算数，次日会**重新提示**（锚点与冷却都以实际交易为准）。回测里的"实际交易"即回测交易明细的每笔成交。

### 6.5 红利网格策略（DIV_GRID）

面向**红利/红利低波**这类低波动、慢牛、均值回归强的 ETF（实测近一年：515080 年化波动 13.7%、512890 12.0%）。核心思想是"底仓吃长期上涨，网格吃来回震荡"。

- **网格模式**：建议**等差**（红利价格区间窄，等差与等比差别不大）。
- **网格下沿 / 上沿 / 格数**：对着近 1~2 年的实际波动区间设。515080 近一年区间 1.395~1.637，取 1.40~1.62 切 11 格 ≈ **每格 1.43%**，是个合理起点。
- **每格单位**：按份额（每格固定份数）或按金额（每格固定金额，价格越低自动买越多份，成本更平滑）。
- **底仓份额**：**卖出下限**，红利建议留足（收益主要来自长期持有）。**满仓份额**：**买入上限**，与可用资金匹配。
- **初始仓位份额**：仅回测首日建仓用；实盘按你实际的持仓判断。⚠️ 要大于底仓份额，否则网格卖不出去。
- **涨破上沿**：红利选**「保留底仓、区间不动」**——慢牛品种一旦清仓就是永久卖飞。
- **跌破下沿**：「买 1 格后观望」即可（红利回撤有限，不必开"区间下方继续按格买入"）。
- **趋势均线天数**：填 0（关闭）。红利下跌本身就是要买的时刻。
- **溢价率闸门**：填 0（关闭）。红利 ETF 溢价常年接近 0（515080 实测 -0.05%）。
- **估值闸门（可选）**：中证红利指数（000922）有 PE 数据，可填 `PE 买入上限`（贵了不买）与 `PE 买入下限`+`低估买入倍数`（便宜了加倍买）。

### 6.6 纳指网格策略（NDX_GRID）

面向**纳斯达克 100 等跨境 ETF**（实测近一年：513300 年化波动 23.3%、区间跨度 39.5%）。这类品种波动大、趋势强、回撤深，**还有一个红利没有的坑：溢价**——实测 513300 当前溢价 **+8.93%**、513500 标普500 达 **+10%**，指数没跌但溢价一收敛就是先亏一笔。

- **网格模式**：建议**等比**（每格固定百分比，价格跨度大、长期抬升时每格利润率一致）。513300 取 2.00~2.80 切 10 格 ≈ **每格 3.4%**。
- **底仓份额**：可以留少一些（如 1000~2000 份）；**满仓份额**是硬约束，深回撤时要留得住子弹。**初始仓位份额**要大于底仓。
- **涨破上沿**：选**「区间上移（移动网格）」**——纳指长期创新高，固定上沿会反复卖飞。区间只会随新高上移、不会自动回落（想重开区间就手工改回上下沿）。
- **跌破下沿**：「买 1 格后观望」；若你愿意在深回撤里继续接，可改「区间下方继续按格买入」（会被满仓上限夹住）。
- **趋势均线天数**：**60**（推荐）。现价低于 60 日均线时**禁止买入**、卖出不受限，避免跌势里一路接飞刀；均线不足 60 根时闸门自动不生效并在建议里说明。
- **溢价率买入上限%**：**3**（推荐）。溢价高于 3% 时禁止买入。QDII 净值公布常滞后 1~2 天，超过「溢价率容忍滞后(天)」（默认 3 天）时视为数据过期、不拦截并提示。
- **回测假设溢价率%**：**留空**。回测没有溢价率历史（平台只存最新一天），留空＝回测跳过溢价闸门（结果会比实盘乐观）；想模拟高溢价环境就填个值，例如 5。
- **PE 闸门**：纳指没有 PE 数据源，填 0（不生效）。

> ⚠️ 两者的**回测口径差异**只在溢价率：实盘用真实溢价率（带滞后容忍），回测用固定假设值或跳过。其余规则（格位、跨格成交、夹取、破边界、MA60）实盘与回测**完全一致**——回测调好的参数可以直接套到实盘。

### 6.7 参数怎么试、要注意什么
- **先回测再启用**：同一个策略改参数各回测一次，对比总收益/最大回撤/交易数（回测只看历史，不代表未来）。
- 注意**数据量与预热**：`windowYears` 需要足够长的估值历史（估值策略会自动往前多加载预热数据）；样本不足 30 个点时百分位不可用。
- 注意**资金约束**：每格/每档份额 × 格数 要与你的实际资金匹配，否则回测里会出现"现金不足按可用现金折算"的情况，和实盘不一致。
- 网格的上沿/下沿要**对着当前价格区间设**（例如取近一年的高/低点附近），设远离现价会导致长期不触发。
- 震荡向上的**满仓份额 × 现价要接近你打算投在这只基金上的钱**：份额配太小（如本金 100 万却只配 3 万元的份额）会让仓位长期只有几个百分点，收益被本金稀释、信号看起来"没效果"。
- 震荡向上的**上涨减仓% 与 下跌加仓% 建议同向设置**（例如都是 5%，或下跌阈值略小以便更快建仓）；把上涨阈值设得比下跌阈值大很多，会偏向"多买少卖"。
- 网格类策略（金字塔/倒金字塔/红利/纳指网格）的**单格幅度建议不低于 2 倍日均波动**：太密会被最低 5 元佣金与滑点吃掉利润。参考口径：格宽 ≈ 年化波动 ÷ 16（红利约 1%~2%、纳指这类约 3%~4%）。
- 红利网格/纳指网格的**初始仓位份额要大于底仓份额**，否则一建仓就贴住卖出下限、网格只买不卖（表单里已加提示）。

### 6.8 每日信号与邮件通知
- 每个**交易日 09:00**（北京时间，盘前）对全部启用策略计算当日信号，写入信号记录（同一基金+策略+日期幂等覆盖，保留已读/已通知标记）。信号基于**上一交易日收盘数据**生成，信号日期即上一交易日。
- **"交易日"是怎么判的（V5.24）**：周六日一律不算；再查**休市名单表 `market_holiday`**（已内置 2026 年剩余休市日：9/25 中秋、10/1~10/7 国庆）；两者都不命中才算交易日。**节假日整轮跳过**——不计算、不发邮件、不发微信，只留一条日志。
  - 这意味着节前最后一个交易日的信号，会在**节后第一个交易日早上**推送（休市期间不发），推送时机不会落在放假那天。
  - ⚠️ **每年补一次**：次年休市安排公布后（通常 11-12 月），往 `market_holiday` 加一行即可，例如 `INSERT IGNORE INTO market_holiday (holiday_date, holiday_name, source) VALUES ('2027-01-01','元旦','manual');`。没补录时系统按"工作日即交易日"退化，并在日志里告警提醒。
  - 平台还会**盘面自判**兜底：交易时段连续两轮取不到当天行情时，判定当天休市并自动把该日期补进名单（来源标记 observed，核对后可手工删除）。
- 当日有**买入/卖出**信号时会发一封信号摘要邮件（内容含基金、方向、价格、理由与免责声明）；无买卖信号不发。
- **微信推送（V5.20）**：与邮件并行、互不影响。需在【平台配置 → 微信通知】填入企业微信自建应用的
  企业 ID / AgentId / Secret 并开启（个人微信扫「微信插件」码后，消息直达个人微信的「企业微信通知」会话）。
  只推 BUY/SELL；微信发送失败只记日志、不影响邮件。
- 信号在【仪表盘】（最近 5 条，展示 基金/日期/方向 三个字段）、**【信号查询】页（全部历史）**与 AI 助手都能看到（问"最近有什么买卖信号"）。已读标记用于区分"新信号"。
- 邮件相关配置（SMTP 服务器/授权码/通知开关）在【平台配置 → 邮件通知】里维护，改完保存即生效（见 10.6）。

### 6.9 信号查询页
- 位置：侧栏【信号查询】（在【交易流水】与【基金对比】之间）。
- **能筛什么**：基金代码（精确）、方向（买入/卖出/持有）、策略（下拉里有全部已注册策略：金字塔网格/倒金字塔网格/震荡向上/红利网格/纳指网格，新增策略会自动出现）、信号日期区间。改任一条件都回到第 1 页重新查询。
- **列含义**：信号日期（信号归属的交易日）、方向（红=买入、绿=卖出、灰=持有）、基金（代码+名称）、策略、信号价（当时的收盘价/净值，4 位小数）、建议说明（含触发理由，如"较锚点上穿一格"）、状态（**未读**红标 / **已邮件通知**灰标）。
- **点击行** = 标记已读并跳转到该基金详情（与仪表盘今日信号卡一致）。
- 与仪表盘的关系：仪表盘那张卡只显示**最近 5 条**（基金/日期/方向，点行标记已读并跳详情）、用于提醒；这一页是**全量可筛选**的查询视角，数据同源（同一张 signal_record 表）。
- 数据是每个交易日 09:00 定时任务算的，当天新导入的基金要到下一个信号时点才有记录；手动补算可在基金详情的策略页签触发。

### 6.10 市场信号页（涨跌榜 / 估值红绿灯 / 技术面与溢价）
- 位置：侧栏【市场信号】（在【信号查询】之后）。**每天自己打开看**的指标看板，不发任何推送；全部指标由库内数据计算，只作参考、不构成投资建议。
- **页签一「涨跌榜」**：自选池全部基金的 7/15/30/60/250 日涨跌幅矩阵，点列头排序，每页 10 条分页（**排序是跨页对全量做的**，不是只排当前页）。**每个窗口的读法不一样**（表头悬停有提示）：7/15 日属于短期——A 股短期（约 1 个月内）反转效应强，**领涨榜不是"能追榜"，领跌榜才是"超跌关注"**；30/60 日是中期动量参考；250 日对应"52 周位置"，接近新高=趋势强，但纯新高策略回测会跑输，只当状态看。
- **页签二「估值红绿灯」**：跟踪指数最新 PE、PE 百分位与灯色（**低于30% 低估=绿 / 30~70% 正常=黄 / 超过70% 高估=红**）、样本天数、股息率 TTM（仅展示、不参与灯色）、PE 数据截至日。**分位窗口可切换**（近3年/近5年/近10年/全历史，默认近10年），窗口越短分位越敏感；样本不足 30 天时分位不展示（显示「无数据」），避免误导。分位算法与基金池、基金详情估值页签完全同口径。
- **页签三「技术面与溢价」**：MA20/60/200 上（红）/下（绿）、趋势汇总（三线全上=多头排列、全下=空头排列、其余=震荡）、回撤深度（现价距历史最高收盘的跌幅）、回撤分位（历史全部交易日回撤中小于当前回撤的占比，90=比历史上 90% 的时间跌得深）、场内 ETF 溢价率。
- **溢价告警阈值**：默认 3%，可自行修改（0.5~50），**修改即时生效、记在浏览器本地**（换浏览器或清缓存会回到默认 3%）。超过阈值的行排在前面，且**基金名字体标红**（不做整行底色）——QDII（纳指/标普等）溢价高企时买入，指数不跌也可能亏溢价收敛的钱。
- **数据范围**：自选池全部基金（含未持仓、含已清仓），顶部可按**标签**和**基金**（可搜索的单选下拉）两个条件组合筛选；筛选后页码自动回第 1 页。**各列数据截至日不同**（行情盘中/15:30、估值 20:30、溢价率随档案同步），以页面各列标注为准。
- 与【信号查询】的区别：那一页是**策略**信号的历史记录（每日 09:00 计算、可推送）；这一页是**全市场指标看板**（打开即算、纯浏览、不写信号表）。

## 7. 回测

### 7.1 怎么发起一次回测
- **参数会自动回填**：策略下拉默认选「你最近一次回测的那个策略」（没回测过就取你已配置的策略），
  并且**自动带出这台基金上一次该策略回测用的参数**（表单下方会有一行小字说明来自哪次回测）——调好的参数不用每次重填；取不到历史就用表单默认值。
  在【策略配置 → 新增策略】里也一样：打开弹框即按当前策略回填上次回测参数，回测满意后可以直接建配置。
- ⚠️ 若换了一只基金，回填的是**该基金自己**的历史参数（不同基金的价格区间/份额不同，不跨基金套用）。
1. 基金详情 → **回测**页签；
2. 选策略（下拉里有全部已注册策略：金字塔网格、倒金字塔网格、震荡向上、红利网格、纳指网格）；
3. 填**策略参数**（表单会带出该策略的界面默认值；如果你已保存过这只基金的策略配置，参数会自动沿用它的值）；
4. 选**开始/结束日期**、填**初始资金**（≥1000 元）；
5. 点【开始回测】→ 记录会以"运行中 → 成功/失败"更新，失败会显示原因。

前提：该基金**在自选池且所选区间有行情数据**（没导入过或区间内无数据会直接失败）。

### 7.2 回测的成交假设（很关键，决定结论是否可信）
| 假设 | 说明 |
| --- | --- |
| 信号时点 | 用**当日收盘数据**产生信号 |
| 成交时点 | **次日成交**（场内按次日开盘价、场外按次日净值），避免"用当天收盘价买卖"的偷价 |
| T+1 | 当日买入的份额**次日才能卖出** |
| 场内费用 | 佣金默认**万 2.5、最低 5 元**（可配） |
| 场外费用 | 申购费默认 **0.15%**（一折）、赎回费默认 **0.5%**（可配） |
| 现金不足 | 按可用现金**折算**可买份额（不会透支） |
| 分红 | 场内按**现金分红**计入现金；场外已含在复权净值里，不重复计 |

### 7.3 回测结果怎么看
- **资金曲线**：策略 vs「买入持有」基准，曲线上用 **红▲＝买入点、绿▼＝卖出点** 把每笔成交标了出来（图例里可以单独隐藏某一类）；悬浮仍显示当日资金值。
- **交易明细表**：每笔成交的日期/方向/价格/份额/手续费/信号理由，与曲线上的标记一一对应。
- **回测列表**（基金详情 → 回测页签上半部分）：除了策略的总收益/最大回撤，还给出「持有总收益%」「持有最大回撤%」（＝期初全仓买入并持有到底的基准表现，用来对比策略是否跑赢躺着不动）、「平均仓位份额」（策略期内平均持有多少份，衡量资金利用程度）；「策略详情」点开可看当时的完整策略配置；「失败原因」超长时省略号显示、鼠标悬浮看全文。历史老回测没有这几个新指标时显示「--」，重新跑一次即可补上。
- **「规模副图」看不见？** 规模历史**自 V5.12 上线日起逐日积累**（每天 +1 个点），数据源只披露当前规模、无法回补历史——积累初期副图里只有右端一两个圆点属正常，勾选框旁会显示已积累天数；数据点本身以圆标显示，积累一段时间后阶梯线自然成形。
- **为什么策略总收益看着比"一直持有"低？**
- **为什么策略总收益看着比"一直持有"低？** 多半是**分母问题**：总收益% 的分母是初始资金，而策略实际只动用了其中一部分（看「平均仓位份额」「平均持仓市值」「平均持仓成本」）。此时要看 **「持仓资产收益率%」＝收益 ÷ 平均持仓成本**（V5.14 起为**成本口径**：分母是"实际投进去的钱"，不随行情虚增，所以平均仓位没打满时它会高于总收益率）。详情页还给出 **「同仓位持有收益%」**（把买入持有基准按平均仓位折算，近似）：**只有和它比较，才知道同样仓位下策略是否跑赢躺着不动**。
- **两个可自检的恒等式**（结果页给了所有输入）：① `总收益率 = 持仓资产收益率 × (平均持仓成本 ÷ 初始资金)`（结果页的「平均成本/本金」就是这个比例）；② 若比例**超过 100%**，说明策略把赚到的钱又投了进去（复利再投入），此时持仓资产收益率**仍可能低于**总收益率——这是数学结果，不是算错。
- 若想让总收益与持有直接可比，把【满仓份额】放大到接近可用资金即可——收益放大的同时**回撤也会同比例放大**，请一并看「最大回撤%」。

### 7.4 回测指标的含义
| 指标 | 算法 |
| --- | --- |
| 总收益率 | (期末总资产 − 初始资金) / 初始资金 |
| 年化收益率 | (1 + 总收益率)^(365 / 回测自然日数) − 1 |
| 最大回撤 | max(1 − 资产(t) / 截至 t 的峰值资产)，同时记录峰值日/谷底日/修复日 |
| 夏普比率 | mean(日收益 − 无风险利率/252) / std(日收益) × √252，无风险利率默认 **2%** |
| 胜率 | 盈利平仓笔数 / 总平仓笔数 |
| 交易数 | 区间内成交笔数（明细逐笔写入，可在结果页翻看） |

### 7.5 回测注意事项与常见失败原因
- **回测不等于实盘**：滑点、成交价、你能否严格执行纪律都不在模型里；参数过拟合（挑历史最优）很常见。
- 常见失败原因：基金不在自选池、区间内无数据、估值策略缺指数估值、参数非法（如 lowPct ≥ highPct）、初始资金过小（买不起一手/一份）。
- 回测记录**永久保存**，可以反复对比不同参数的结论。

## 8. 基金对比

### 8.1 怎么用
【基金对比】选 2~N 只自选基金 → 归一化对比曲线（起点=100）+ 区间表现表。适合"红利 vs 宽基""同指数不同 ETF"的比较。

### 8.2 口径与限制
- 对比只能在**自选池内**的基金之间进行；跨市场（ETF vs 场外）也能比，但注意场外是净值、场内是前复权价，曲线是同起点归一化后的相对走势。
- 区间表现的截止日按各自最新数据日；若某只基金数据滞后，会在表里标出它的实际截止日，别把"数据没更新"误读成"跑输"。

### 9.2 数据新旧怎么看（V5.19 起仪表盘不再显示同步状态卡）
- 【仪表盘】的同步状态卡已替换为**交易流水卡**；判断数据新不新改看【基金池】的「最后同步」列。
- 同步本身不受影响：定时任务照跑，**同步异常告警邮件**（22:05）仍会对滞后基金发提醒；手动同步入口在【基金池】与【基金详情】。
- 手动同步与每日定时任务**用同一把分布式锁**，不会互相打断或重复写。

## 10. 平台配置

### 10.1 AI 模型配置：厂商、Base URL、Token
位置：侧栏【平台配置】→【AI 模型配置】卡片。
- **厂商**：智谱 / 千问 / DeepSeek / Kimi / MiniMax（都是 OpenAI 兼容端点，换个厂商只是换个地址与 Key）。
- **Base URL**：切换厂商会自动填入该厂商默认地址；用自建/代理地址可直接改。
- **Token**：按厂商签发，**每个厂商各存一份**。已配置过时输入框显示"已配置（****后四位），留空不改"——你切换厂商或改单价时**不用重填 Token**。

### 10.2 模型怎么选
- 点【拉取模型列表】会调该厂商的 `/models` 接口，列出可用模型，并对内置已知的**免费档**标注"（免费）"；厂商不提供该接口时可直接手工输入模型名。
- 免费档模型（如智谱的 glm-4-flash）指令遵循能力弱一些，边界问题上表现不如付费档；追求稳定可换付费模型。
- 选好模型后点【保存并生效】，**立即生效，无需重启应用**。

### 10.3 单价怎么填（决定了"AI用量统计"里的钱准不准）
- 三个单价都是**元 / 百万 token**，按厂商官网当前价填，**按厂商各存一份**（切厂商自动用那一家的价）。
- **输入单价**：普通输入 token 的价；**缓存单价**：命中提示缓存的输入 token 的价（多数厂商明显便宜，DeepSeek 尤其便宜）；**输出单价**：生成 token 的价。
- 缓存单价留 0 时按输入单价计（不会漏算）；**免费模型三个都填 0**（费用恒为 0）。
- 单价是**快照**：改价只影响之后产生的流水，历史费用不会被改写。

### 10.4 连通性自检
点【连通性自检】用当前表单里的地址/Token/模型发一句最小请求，几秒内返回"连通正常（模型已响应，耗时 x ms）"。自检不修改配置，但**会真实消耗 token**并记一行"自检"用量。

### 10.5 切换厂商：选中 + 保存才切换（且不覆盖别家）
- **每个厂商的配置各存一份**：Base URL、模型、Token、三个单价互不覆盖。切到旧厂商，它的配置还在，Token 也不用重填。
- 「当前使用」= 对话实际调用的那家。下拉里会标出「当前使用」与「已配置」。
- **选中某厂商只是把它的配置载入表单**；点【保存并生效】才会真正切过去（避免误点下拉把对话搞挂）。卡头会提示"当前使用：X（保存后才切换）"。
- 前提：切到的那家必须已配 Token（或本次填上），否则对话会提示"尚未配置模型"。

### 10.6 账号、通知邮箱与 SMTP
- 【基本信息】改昵称与**通知邮箱**（信号/告警邮件的收件人）。
- 【安全设置】改密码（改完需重新登录，会全端下线）；连续 5 次密码错误会锁定 10 分钟，会话有效期 7 天。
- 【邮件通知】卡片可**直接编辑并保存**：SMTP 服务器、端口、通知开关、发件账号、授权码、发件人、收件人。
  配置存在**本平台数据库**里，点【保存邮件配置】**立即生效、无需重启应用**（授权码也不再写在配置文件或环境变量里）。
- **打码值 = 沿用原值**：发件账号与授权码回显为 `83***@qq.com` 这类打码值时，表示"已存着这份配置"，
  **不改动直接保存就是保持原值**，不会把打码值写进去；要换账号或授权码时把整段重新填一遍即可。
- **收件人留空**则用上面资料里的通知邮箱；两者都没有时发送会提示先补一个。
- 【发送测试邮件】与【通知开关】相互独立：**开关关掉后仍可手动发测试邮件**（便于先验证参数再开自动发送）。
- **测试按"界面当前填写"来（V5.26）**：表单改了还没保存，点【发送测试邮件】/【发送测试消息】测的就是眼前这套参数，不必先保存；留空或打码的字段（授权码、Secret、打码的企业 ID）自动沿用已存值。测试本身**不会**把你填的内容写进配置——要生效还是得点【保存】。
- 常见失败原因：端口填错（QQ 邮箱 SSL 用 465、STARTTLS 用 587）、把**登录密码当授权码**填了（要去邮箱后台生成授权码）、
  授权码过期，或短时间内连发多封被上游临时限流（稍后重试即可，界面会给出中文原因）。

## 10.8 仓位配置（每周二自动检查）

- **是什么**：给五类资产各设一个"占总资产的目标范围"（现金 / A股 / 美股 / 亚太 / 欧洲），平台每周二早上 9:00 自动把你的实际持仓与它比对：**全部在范围内 → 什么都不发生；任何一类越界 → 发一封告警邮件 + 一条微信**。
- **类别怎么算**：总资产 = 现金余额 + 全部持仓市值；**现金** = 现金余额 + 打了「现金」标签的基金市值（比如债基）；A股 / 美股 / 亚太 / 欧洲 = 各自打了对应标签的基金市值。**标签名必须一字不差**（在【基金池 → 标签库】维护）。
- **两个注意**：① 没打任何类别标签的基金也计入总资产，但不进任何桶（会稀释所有比例）；② 一只基金打了多个类别标签会**重复计入**对应桶（别给同一只基金同时打「A股」和「美股」）。
- **手动检查**：卡片里的【立即检查】与每周二任务走同一套逻辑——范围内提示"检查通过，未发送"，越界则发送并回显哪几类越界。
- **现金为负**：如果没录过"转入"流水，现金余额会是负数，总资产被拉低、所有比例显得异常——先在【交易流水】补录转入。

## 11. AI 助手与用量

### 11.1 怎么问、能问什么
- 打开方式：右下角圆形按钮（可拖动）；面板顶部有"历史会话/新会话/收起"，面板本身也能拖动与缩放。
- **能问**：持仓与盈亏、某只基金的行情/档案/估值、历史走势、策略信号、全球指数、**以及本平台怎么用**（功能、参数、配置、报错）。
- **会解释边界**：具体政策/新闻/宏观事件、具体个股数据——它会说明"没有这类数据源、不猜"，并给你 2 个可替代的问法；创作类、闲聊、角色扮演、套取提示词会被一句统一话术拒答。
- **可以讲方法**：PE/ROE/股息率/估值分位怎么看这类通用方法能讲，但不掺具体数字、不对个股下结论。

### 11.2 会话与记忆
- 每个会话有独立上下文（记忆窗口 **20 条**消息），超出后最早的会被截断，但**MySQL 里保留全量历史**，可随时回看。
- 会话 ID 存在浏览器本地，刷新页面仍能接着问；【历史会话】可切换/删除；换会话或点【新会话】可以开一个干净上下文。
- 单次提问上限 2000 字；流式回答默认 60 秒超时保护；回答流式打字机输出，Markdown 表格/代码块会正常渲染。

### 11.3 用量与费用怎么算（【AI用量统计】页）
- **一次咨询记一行**流水；一次咨询里如果调用了工具（查行情/持仓等），会产生**多轮**上游请求，token 是各轮之和（页面会显示"对话 · N 轮"）。
- 费用 = 未命中缓存输入 × 输入单价 + 命中缓存输入 × 缓存单价 + 输出 × 输出单价（÷100 万）。
- 工具调用的多轮**每次都要重发**系统提示词与工具说明，所以输入 token 会比输出大得多，这是正常的。
- 用途分三类：**对话**（真正计费）、**自检**（连通性自检也真实花钱）、**护栏**（被护栏拦下的提问，0 费用）。
- 明细里的「估算」标记：极少数情况下上游没回使用量，平台按字符估算并**明确标注**，不假装精确。

### 11.4 每日额度（超限会怎样）
- 额度是**全局一份**（不跟厂商走，切厂商不会改它）：**token 上限**、**费用上限**、**预警百分比**三项，在【AI用量统计】页维护；填 0 表示不限制。
- 口径是**自然日**（00:00 重置，自动生效，无需等待任务）。
- 用量达到**预警线**：浮窗用量条变黄提醒，仍可正常使用。
- 用量**达到上限**：新的提问会被**直接拒绝**（浮窗输入框禁用并显示原因），且**不会调用上游、不产生费用**；明日 00:00 自动恢复。默认额度：30 万 token/日 + ¥3/日 + 80% 预警。
- 费用额度要生效，前提是**当前厂商的单价填了**（未填时费用恒为 0，页面会提示"按费用的限额不生效"）。

## 12. 数据同步与定时任务

### 12.1 每天几点在做什么（时间表）

### 12.2 数据滞后怎么看、手动同步怎么做
- 看【基金池 → 最后同步】列；在【基金池】或【基金详情】点同步即触发一次增量同步。
- 手动同步是**增量**（从本地最新日期+1 拉到今天）；历史数据有洞时用【数据导入】重导（覆盖刷新）。
- 盘中手动同步能拿到当日实时数据，次日收盘任务会用官方收盘数据覆盖修正。

### 12.3 为什么 ETF 每天要全量重拉（前复权口径）
前复权价以"最新价格"为基准，**每次分红除权后，全部历史前复权价都会整体变化**。如果只做增量追加，历史段会停留在旧口径，曲线与指标就会出现"断层"。
所以平台的选择是：**每日全量覆盖**（一只基金一次请求、约 2400 行写入），简单且绝对正确；盘中手动同步仍用增量，次日全量任务自动纠正口径。

### 12.4 从日志排查问题怎么找（V5.38 起每个任务都有"开始/结束"日志）

- **每个定时任务执行都会打两条 INFO**：`定时任务[sync:watch]开始执行` … `定时任务[sync:watch]执行结束，耗时[19ms]`；**失败**则打一条 ERROR（含完整堆栈）`定时任务[index:quotes]执行失败，耗时[9563ms]`——**有开始没结束（也没失败）说明进程被重启/杀掉了**。
- **中括号里那串 `job:xxx:20260928:2` 是 traceId**（`job:任务名:日期:当日第几轮`）：**本轮任务里所有日志都带同一个 traceId**，包括它调用的 service、MyBatis SQL、Redis 命令。所以排查某一次执行，直接搜这个 traceId 就能捞出全过程，不会被别的任务和网页请求的日志淹没。
- 手动点【立即检查】（仓位配置）也走同一套日志，traceId 是 `job:allocation:manual:日期:序号`，与每周二自动跑的 `job:allocation:weekly:…` 一眼可分。
- 想确认"任务到底跑没跑"：搜任务名（如 `sync:watch`）；**非交易日/周末的跳过也会留一条** INFO（`今日（2026-10-01）非交易日（休市名单），任务[nav]跳过：不执行`），所以"没日志"才是异常。

## 13. 常见问题 FAQ

### 13.1 数据类
- **某只基金查不到行情**：先确认它在不在自选池（AI 只会查自选池内的基金）；不在就【数据导入】导入。
- **数据日期很旧/没更新**：看【基金池 → 最后同步】列；在基金详情点同步重试；仍不更新就是上游接口抖动，稍后再试（日志关键词"同步失败"）。
- **股息率列是 `--`**：该基金没有分红记录，或未复权价格数据还没补齐（每日全量同步会补上）。
- **估值百分位是 `--`**：跟踪指数未识别，或指数估值历史不足（少于 30 个采样点不给百分位）。

### 13.2 记账类
- **持仓和券商对不上**：核对流水金额是否按对账单填（价格是派生的，改金额比改价格准）；确认没有漏记分红。
- **现金余额是负的 / 转不出去**：现金 = 转入−转出−净投入，为负通常意味着少了一笔"转入"（把外部资金补记成一笔转入即可）。已知口径限制见 3.4 节末。
- **分红记完成本变了**：这是设计如此——现金分红会冲减持仓成本并计入已实现盈亏。
- **想把红利再投资**：拆成"分红 + 买入"两笔（见 5.3）。

### 13.3 AI 类
- **提示"尚未配置模型"**：到【平台配置 → AI 模型配置】选厂商、填 Token、拉取并选择模型，保存即生效。
- **提示"今日 AI 用量已达上限"**：到【AI用量统计】页看用量与额度，调高上限（或明日 00:00 自动恢复）；注意超限时**不会调用上游**，所以不会偷偷花钱。
- **提示"AI 服务暂时不可用（原因）"**：多为上游接口异常或超时；可先用【连通性自检】确认 Key/地址/模型是否正常，再重试。
- **回答里的数字**：凡是价格、持仓、盈亏、信号这类数字都来自工具实时取数；如果它说"查不到"，通常就是自选池里没有这只基金或数据未同步。
- **不想让它乱花 token**：把每日 token/费用额度设小（如 5 万 token/日），超限自动拒绝。

### 13.4 运维类
- **启动/停止**：仓库根目录 `sh build.sh`（会先停应用再打包，避免 jar 被占用）与 `sh stop-app.sh`；启动 `java -jar quant-web/target/quant-web-1.0.0.jar`。默认端口 **8080**。
- **依赖**：MySQL（库名 `quant`，开发环境 root/root）、Redis（会话与记忆窗口）；表结构由 `schema.sql` 在启动时**幂等**创建/迁移，升级只需替换 jar 重启。
- **首次启动账号**：`admin` / `admin123`（来自 `quant.init.admin-username/password`），请登录后立即改密码。
- **备份**：`deploy/mysql-backup.sh` 做数据库备份；`docs/` 是研发文档，与运行数据无关。
- **日志**：应用日志在 `logs/`（含按天滚动与错误单独文件）；接口调用日志会打 traceId，便于串联排查。

## 14. 术语与口径速查

### 14.1 价格类
| 术语 | 含义 |
| --- | --- |
| 单位净值 | 场外基金每份的净值（未复权） |
| 复权净值 | 把分红再投资后的累计净值，用于算收益/回测（本平台场外用它撮合） |
| 前复权价 | 以**最新价**为基准回溯调整过的历史价格；**最新一日就是真实成交价**，历史段被压低（分红越多越低） |
| 未复权价 | 当日真实成交价；历史股息率的分母必须用它 |

### 14.2 收益类
| 术语 | 含义 |
| --- | --- |
| 净投入 | 真正投进持仓的钱：Σ买入(含费) − Σ卖出净额 − Σ分红净额 |
| 现金余额 | (Σ转入 − Σ转出) − 净投入 |
| 总资产 | 持仓市值 + 现金余额 |
| 累计收益 | 总资产 − 净投入（排除外部转入转出的真实盈亏） |
| 摊薄成本价 | 剩余持仓成本 ÷ 持有份额（买入含手续费，卖出按它结转） |
| 已实现盈亏 | 卖出/分红已经落袋的盈亏 |
| 浮动盈亏 | (最新价 − 成本价) × 份额，尚未落袋 |

### 14.3 估值与分红类
| 术语 | 含义 |
| --- | --- |
| PE 百分位 | 当前 PE 在近 N 年历史中的分位（越低越便宜）；分档加/减仓策略的依据 |
| 股息率（TTM） | 过去 12 个月每份分红合计 ÷ 当日真实价格 |
| 单次分红股息率 | 某一次分红 ÷ 除息日真实价格 |
| 溢价率 | 仅 ETF：(收盘价 − 当日净值) / 净值；正数表示场内买贵了 |
| 最大回撤 | 从峰值到谷底的最大跌幅（同时记录峰、谷、修复日） |
| 夏普比率 | 单位波动换来的超额收益（无风险利率默认 2%） |
