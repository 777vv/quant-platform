# 个人量化投资助手 · 使用手册

> 本手册讲**这个平台怎么用**：每个功能做什么、在哪里点、参数是什么意思、有哪些注意事项、出错怎么办。
> 应用内可在侧栏【使用手册】阅读；AI 助手也读同一份手册，所以"这个功能怎么用"直接问 AI 也行（问它比翻这里更快）。
> 手册只讲"怎么用"；每个功能为什么这么设计、口径的取舍，见 `docs/02-技术文档.md`。

## 1. 快速上手

### 1.1 这是什么平台（一句话与三条边界）
这是一个**给自己用的指数基金投资助手**：管住自选池、算清持仓与收益、按策略给买卖建议、每天早上告诉你该看什么，并提供回测验证。

三条边界先记住，能省很多困惑：
1. **只给建议，不自动交易**——平台不会替你下单，所有买卖都由你在券商 App 自己操作。
2. **只支持指数基金**：场内 ETF 与场外指数基金；不支持个股、不支持期货外汇、不支持主动管理型基金。
3. **数据来自东方财富公开接口**，只覆盖"你自选池里的基金"，没导入的基金查不到行情。

### 1.2 第一次使用的四步
1. **登录**：打开 `http://localhost:5173`，用管理员账号登录（默认 `admin` / `admin123`，登录后请到【平台配置 → 安全设置】改密码）。
2. **导入一只基金**：【数据导入】→ 输入 6 位代码（如 `510300`）→ 点【校验】→ 确认类型是"场内ETF/场外指数基金"→ 点【开始导入】→ 等进度条走到完成（一只基金约 10~60 秒，ETF 会写入 2000+ 条日 K）。
3. **记一笔持仓**（可选）：【基金池】→ 点基金名字进详情 → 【交易流水】页签 → 新增买入（**只填成交金额与数量**，价格自动算）。
4. **看今日结论**：【仪表盘】看总资产与当日盈亏；【AI用量统计】旁边的 AI 浮窗（右下角圆形按钮）可以直接问"我现在持仓怎么样""最近有什么买卖信号"。

### 1.3 数据从哪来、什么时候更新
- 行情/净值/估值全部来自**东方财富公开接口**，每天由定时任务自动同步（时间表见第 12 章）。
- 你导入或同步后，数据存在本地 MySQL 里；页面读的是本地库，不实时请求上游，所以**断网也能看历史**。
- 判断数据新不新：看【基金池】的「最后同步」列或【仪表盘】的同步状态区；滞后会标红并可一键重试。

## 2. 数据导入

### 2.1 支持什么、不支持什么
| 项目 | 说明 |
| --- | --- |
| 支持 | **指数型基金**：场内 ETF（如 510300）、场外指数基金（如 110003） |
| 不支持 | 股票型/混合型/债券型等主动基金、个股、期货外汇、货币基金 |
| 数据范围 | 近 10 年；成立不足 10 年的自成立日起 |
| 导入内容 | 场内：前复权日 K（开高低收、成交量额）；场外：单位净值 + 复权净值；另外同步该基金**跟踪指数**的历史估值（PE） |

不支持的品种在校验阶段就会被拦下，并给出具体原因（例如"非指数型基金（类型：混合型-灵活），平台仅支持指数基金"）。

### 2.2 导入步骤与校验结果的三种状态
1. 【数据导入】输入 6 位代码 → 点【校验】。校验会去上游确认这只基金存在、类型合格、并识别它的跟踪指数。
2. 看「池内状态」标签，**三种状态对应三种含义**：
   | 状态 | 含义 | 按钮 | 点下去会发生什么 |
   | --- | --- | --- | --- |
   | **新基金** | 从没导入过 | 【开始导入】 | 全量拉取历史数据并加入自选池 |
   | **已在自选池** | 已导入且在池里 | 【重新导入（覆盖刷新）】 | 整段重拉历史数据并覆盖本地，不会产生重复 |
   | **已移出自选（历史数据保留）** | 导入过、后来被你移出自选 | 【恢复到自选池并导入】 | 重新放回自选池，并覆盖刷新历史数据 |
3. 点按钮后进度条会显示阶段（拉取日K/计算复权净值/写入/同步估值），完成后可到【基金池】看到它。

### 2.3 导入是"整段覆盖刷新"，不是只补缺的几天
这是最容易误解的一点：**历史导入会从成立日（或近 10 年）整段重新拉取，然后覆盖本地数据**，而不是只补最新几天。原因是**前复权价会随每次分红除权整体变化**——只追加会让新旧数据口径不一致（详见第 12.3 节）。
- 只想补最新几天：用【基金池】或详情页的**同步**按钮（那是增量 upsert）。
- 覆盖刷新不会产生重复行（先删后插 + 唯一键兜底），可以放心重复点。

### 2.4 导入失败怎么办
- 进度条会显示失败阶段与原因；常见原因是上游接口抖动或限频（返回空数据/超时）。
- 处理：等 1~2 分钟重试即可；反复失败先确认网络能否访问东方财富，再看后台日志 `logs/`（关键词"历史导入失败"）。
- 导入中断不会污染已有数据（写入是事务化的：要么整段替换成功，要么保持原样）。

## 3. 基金池

### 3.1 自选池是什么
自选池 = 你**导入过且没有移出**的基金集合。平台的行情同步、策略信号、AI 查询都只覆盖自选池内的基金——所以"查不到某只基金的行情"通常是因为它不在自选池。

### 3.2 列表每一列怎么读
| 列 | 含义 / 口径 |
| --- | --- |
| 代码 / 名称 | 名称后带小标签表示**持仓中** |
| 跟踪指数 | 该基金跟踪的指数（如 沪深300指数 000300），估值百分位用它关联 |
| 标签 | 你自定义的分类（红利/宽基/债券…），可筛选 |
| 最新价/净值 | ETF 是前复权收盘价，场外是单位净值（数据日期看「最后同步」） |
| 涨跌幅% | 相对前一交易日的涨跌 |
| 规模(亿) | 净资产规模，来自基金档案（季末披露，注意截止日） |
| 溢价率 | 仅场内 ETF 有意义：= (收盘价 − 当日净值) / 净值；正数表示场内买贵了 |
| 运作费率 | 管理费/托管费(+销售服务费) 合计（%/年） |
| 股息率(TTM) | 过去 12 个月每份分红合计 ÷ 当日真实价格（口径见 4.4） |
| 估值百分位% | 跟踪指数 PE 在近 N 年中的分位（越低越便宜），无估值数据显示 `--` |
| 已配策略 | 该基金是否已配置策略（有/无） |
| 最后同步 | 本地最新数据日期；滞后会在仪表盘标红 |

### 3.3 标签、筛选与分页
- 在【基金池】上方可**关键词搜索**（代码或名称）、按**标签**筛选，都是服务端筛选（作用于全部数据，不是只筛当前页）。
- 支持跨页勾选后批量操作；分页每页可选 10/20/50/100 条。
- 标签库在【基金池 → 管理标签】里维护（预定义 + 自定义），给基金打标签在列表的标签列点开编辑。

### 3.4 移出自选（软删）与恢复
- **移出自选 = 软删**：基金不再出现在列表与同步范围里，但**历史数据（日K/净值/估值/流水）全部保留**，标签关联也保留。
- **持仓中的基金不允许移出**：必须先卖出全部份额（防止持仓失去行情来源）。已清仓但有历史流水的可以移出。
- **想恢复**：到【数据导入】输入代码 → 校验会显示「已移出自选（历史数据保留）」→ 点【恢复到自选池并导入】。恢复后它又会回到自选池并参与每日同步。
- 注意（已知口径限制）：净投入只统计**当前仍在自选池**的基金，所以把已清仓基金移出自选后，它的历史买卖不再计入净投入，现金余额与已实现盈亏会出现缺口。若你经常这样做，先看第 13.2 节。

## 4. 基金详情

### 4.1 页签总览
进入基金详情（点基金名）后是六个页签：**行情走势 / 指数估值 / 交易流水 / 策略配置 / 回测**，以及顶部的档案区（规模、费率、溢价率、最后同步等）。
档案类字段（规模/费率/跟踪指数）**每天刷新一次**，可在详情页手动强制刷新；溢价率每次同步时自动算。

### 4.2 行情走势图怎么用
- **区间选择**：右上角下拉（近3个月/1年/3年/5年/10年），或直接选**自定义日期区间**（两者互斥，选自定义后下拉失效）。
- **框选**：在图上按住拖动即框选一段，日期区间会自动回填并重新加载（图表已内置框选工具，不必点工具箱图标）。
- **技术指标**：副图可切换成交量、MACD；主图可叠加 MA、BOLL（指标会**往前多取 150 天预热**，所以窗口开头的指标不会失真或空缺）。
- **图表高度**：副图开关变化时画布高度与网格自动重排。

### 4.3 图上的 b / s / q 标记是什么意思
- `b` = 买入、`s` = 卖出：取你在本平台记录的**交易流水**；
- `q` = 分红除息：取东方财富的分红送配记录（**全部除息日**，不只你持有的部分）。
- 标记是按图上可见窗口自动裁剪的散点，不参与悬停提示（避免用价格污染 tooltip）；图上有一条说明文字。

### 4.4 股息率副图与两个股息率口径
- **单次分红股息率** = 每份分红 ÷ 除息日真实价格；
- **TTM 股息率** = 过去 12 个月每份分红合计 ÷ 当日真实价格（红利类指数/基金报"股息率"时通常用这个口径，平台默认展示它）；
- 分母用的是**未复权真实价格**：本平台 ETF 存的是前复权价，它把历史价格压低了，直接当分母会系统性高估历史股息率，所以专门存了未复权收盘价。
- 副图 = 紫色阶梯线（TTM 股息率）+ 蓝色散点（每次分红），独立百分比轴；无分红的基金副图为空。

### 4.5 「区间表现」表的口径
区间表现（交易日/区间涨跌幅/最大回撤/年化波动率）的口径是**图上当前可见的那一段**（所见即所测）：缩放或框选后自动重算，并且**不重新请求接口**（用已加载序列本地计算）。所以"表里的数字"和"图上看到的范围"始终一致。

### 4.6 指数估值页签
展示该基金跟踪指数的 PE 历史与百分位（数据来自中证指数等公开源，与"估值百分位"列同源）。跟踪指数未识别或缺失时，会明确提示"未识别跟踪指数"，而不是给一个错的图。

## 5. 记账与持仓

### 5.1 五种交易类型
| 类型 | 需要填 | 说明 |
| --- | --- | --- |
| 买入 | 基金、日期、**成交金额 + 成交数量**、手续费(可 0) | 价格自动算 |
| 卖出 | 同上 | 按摊薄成本结转已实现盈亏 |
| 分红 | 基金、日期、**金额**（默认现金分红，税前） | 计入已实现收益并冲减成本 |
| 转入 | 日期、金额（不关联基金） | 账户级资金划入，现金增加 |
| 转出 | 日期、金额（不关联基金） | 账户级资金划出，**不能超过现金余额** |

### 5.2 买入/卖出：只填金额和数量，价格是算出来的
- 成交价字段是**只读**的，等于 `成交金额 ÷ 成交数量`，保留 4 位小数。
- 为什么这样设计：对账单上的**金额**最准（含各种费用尾差），手填价×量常与实际扣款对不上。
- 保存前会显示**实时预估**（持有份额、成本价、现金、已实现盈亏的变化），可以先看一眼再保存。

### 5.3 分红怎么记（含红利再投资）
- 默认按**现金分红（税前）**处理：只填金额，价格/份额提交 0，分红计入已实现收益并冲减持仓成本。
- **红利再投资**请拆成两笔：先记「分红」（金额），再记「买入」（金额=分红額、数量=新增份额）。这样两件事都能单独追溯。
- 场外基金的分红也可能体现在净值里（累计净值口径），本平台的分红记录以东方财富的分红送配数据为准（图上的 `q` 标记）。

### 5.4 现金与收益怎么算（三个公式）
```
净投入   = Σ买入(含手续费) − Σ卖出净额 − Σ分红净额
现金余额 = (Σ转入 − Σ转出) − 净投入
总资产   = 持仓市值 + 现金余额
```
- 所有口径都由**一个服务**统一算出（前端只展示），所以页面之间不会打架。
- **累计收益 = 总资产 − 净投入**（即把"外部转进来的钱"排除后的真实盈亏）。
- 转出额度上限 = 现金余额（现金为负时不允许任何转出）。

### 5.5 持仓、成本与盈亏怎么算
- 持仓由**交易流水自动重算**（不是手工维护的表）：份额加减、成本摊薄。
- **摊薄成本价** = 剩余持仓成本 ÷ 持有份额；买入会把手续费计入成本，卖出按摊薄成本结转。
- **已实现盈亏** = 卖出金额 − 手续费 − 卖出份额 × 成本价（分红也计入已实现）。
- **浮动盈亏** = (最新价 − 成本价) × 份额；**当日盈亏** = (最新价 − 前一日价) × 份额。

### 5.6 编辑与删除流水的规则
- 流水可编辑/删除，改完持仓与收益会立即重算；删除末页最后一条会自动回退一页。
- 编辑成"转出"时会重新校验额度上限（会排除原记录自身，避免把自己挡住）。
- 建议：只改错别字/金额；如果只是记错基金，删除后重记更干净。

## 6. 策略配置与买卖信号

### 6.1 策略在哪里配、启用是怎么生效的
- 位置：基金详情 → **策略配置**页签 → 新增/编辑。同一只基金每种策略只能配一套（唯一键：基金+策略类型）。
- **启用（enabled）**：只有启用的策略才参与每日 21:00 的信号计算与邮件；停用后仍可用来回测。
- 参数以 JSON 存在库里，保存时会**立即校验**（范围不对直接报错，不会存进去）。

### 6.2 网格交易策略（GRID）：每个参数的含义
策略逻辑：以锚点价为基准，价格每**下穿一格**买入一份、每**上穿一格**卖出一份；**突破上沿清仓、跌破下沿观望**；锚点随信号移动一格。

| 参数（界面名） | 字段 | 含义 | 取值范围 / 界面默认 |
| --- | --- | --- | --- |
| 网格模式 | `mode` | 等差（每格价格差固定）或等比（每格比例固定） | `arithmetic` / `geometric`，默认等差 |
| 网格上沿 | `upper` | 区间上界价格；**现价高于它 → 建议清仓离场** | >0，默认 5.5 |
| 网格下沿 | `lower` | 区间下界价格；**现价低于它 → 区间外观望（不买不卖）** | >0 且应小于上沿，默认 3.0 |
| 格数 | `grids` | 上下沿之间分成几格（决定触格密度） | 2~100，默认 10 |
| 每格份额 | `sharePerGrid` | 每触发一格买/卖的份额 | ≥1，默认 2000 |
| 底仓份额 | `basePosition` | 回测开始时一次性建立的底仓（首次建仓用） | ≥0，默认 4000 |

参数怎么调：格数越多、每格份额越小 → 交易越频繁、单笔越小（适合波动大但区间稳的品种）；上沿设太低容易被"清仓"，下沿设太高容易长期观望。

### 6.3 估值百分位策略（VAL_PERCENTILE）：每个参数的含义
策略逻辑：用跟踪指数近 `windowYears` 年的 PE 百分位 `p` 分档——`p ≤ 低估阈值` 时按档位**加仓至 底仓 + k×每档份额**（越低档买越多）；`p ≥ 高估阈值` 时按档位**减仓至 底仓 × (1 − k/分档数)**；区间内维持不变。

| 参数（界面名） | 字段 | 含义 | 取值范围 / 界面默认 |
| --- | --- | --- | --- |
| 低估阈值% | `lowPct` | 低于该百分位视为低估，开始分批加仓 | 1~49，默认 25 |
| 高估阈值% | `highPct` | 高于该百分位视为高估，开始分批减仓 | 51~99，默认 75 |
| 分档数 | `steps` | 低估/高估各分几档（决定分批密度） | 1~10，默认 5 |
| 回看窗口(年) | `windowYears` | 计算百分位回看多少年历史 | 1~30，默认 8 |
| 每档份额 | `sharePerStep` | 每降/升一档加/减的份额 | ≥1，默认 3000 |
| 底仓份额 | `basePosition` | 基准持仓（减仓时按它的比例计算） | ≥0，默认 5000 |

必须满足 `0 < lowPct < highPct < 100`，且**该基金的跟踪指数要有估值数据**（没有则信号为"数据不足"，不会给错建议）。

### 6.4 参数怎么试、要注意什么
- **先回测再启用**：同一个策略改参数各回测一次，对比总收益/最大回撤/交易数（回测只看历史，不代表未来）。
- 注意**数据量与预热**：`windowYears` 需要足够长的估值历史（估值策略会自动往前多加载预热数据）；样本不足 30 个点时百分位不可用。
- 注意**资金约束**：每格/每档份额 × 格数 要与你的实际资金匹配，否则回测里会出现"现金不足按可用现金折算"的情况，和实盘不一致。
- 网格的上沿/下沿要**对着当前价格区间设**（例如取近一年的高/低点附近），设远离现价会导致长期不触发。

### 6.5 每日信号与邮件通知
- 每个**交易日 21:00** 对全部启用策略计算当日信号，写入信号记录（同一基金+策略+日期幂等覆盖，保留已读/已通知标记）。
- 当日有**买入/卖出**信号时会发一封信号摘要邮件（内容含基金、方向、价格、理由与免责声明）；无买卖信号不发。
- 信号在【仪表盘】与 AI 助手都能看到（问"最近有什么买卖信号"）。已读标记用于区分"新信号"。
- 邮件相关配置（SMTP 服务器/授权码/通知开关）在【平台配置 → 邮件通知】里维护，改完保存即生效（见 10.6）。

## 7. 回测

### 7.1 怎么发起一次回测
1. 基金详情 → **回测**页签；
2. 选策略（下拉里有全部已注册策略：网格交易、估值百分位）；
3. 填**策略参数**（表单会带出该策略的界面默认值；如果你已保存过这只基金的策略配置，参数会自动沿用它的值）；
4. 选**开始/结束日期**、填**初始资金**（≥1000 元）；
5. 点【开始回测】→ 记录会以"运行中 → 成功/失败"更新，失败会显示原因。

前提：该基金**在自选池且所选区间有行情数据**（没导入过或区间内无数据会直接失败）。

### 7.2 回测的成交假设（很关键，决定结论是否可信）
| 假设 | 说明 |
| --- | --- |
| 信号时点 | 用**当日收盘数据**产生信号 |
| 成交时点 | **次日成交**（场内按次日开盘价、场外按次日净值），避免"用当天收盘价买卖"的偷价 |
| T+1 | 当日买入的份额**次日才能卖出** |
| 场内费用 | 佣金默认**万 2.5、最低 5 元**（可配） |
| 场外费用 | 申购费默认 **0.15%**（一折）、赎回费默认 **0.5%**（可配） |
| 现金不足 | 按可用现金**折算**可买份额（不会透支） |
| 分红 | 场内按**现金分红**计入现金；场外已含在复权净值里，不重复计 |

### 7.3 回测指标的含义
| 指标 | 算法 |
| --- | --- |
| 总收益率 | (期末总资产 − 初始资金) / 初始资金 |
| 年化收益率 | (1 + 总收益率)^(365 / 回测自然日数) − 1 |
| 最大回撤 | max(1 − 资产(t) / 截至 t 的峰值资产)，同时记录峰值日/谷底日/修复日 |
| 夏普比率 | mean(日收益 − 无风险利率/252) / std(日收益) × √252，无风险利率默认 **2%** |
| 胜率 | 盈利平仓笔数 / 总平仓笔数 |
| 交易数 | 区间内成交笔数（明细逐笔写入，可在结果页翻看） |

### 7.4 回测注意事项与常见失败原因
- **回测不等于实盘**：滑点、成交价、你能否严格执行纪律都不在模型里；参数过拟合（挑历史最优）很常见。
- 常见失败原因：基金不在自选池、区间内无数据、估值策略缺指数估值、参数非法（如 lowPct ≥ highPct）、初始资金过小（买不起一手/一份）。
- 回测记录**永久保存**，可以反复对比不同参数的结论。

## 8. 基金对比

### 8.1 怎么用
【基金对比】选 2~N 只自选基金 → 归一化对比曲线（起点=100）+ 区间表现表。适合"红利 vs 宽基""同指数不同 ETF"的比较。

### 8.2 口径与限制
- 对比只能在**自选池内**的基金之间进行；跨市场（ETF vs 场外）也能比，但注意场外是净值、场内是前复权价，曲线是同起点归一化后的相对走势。
- 区间表现的截止日按各自最新数据日；若某只基金数据滞后，会在表里标出它的实际截止日，别把"数据没更新"误读成"跑输"。

## 9. 仪表盘

### 9.1 各卡片口径
| 卡片 | 口径 |
| --- | --- |
| 总资产 | 持仓市值 + 现金余额（见 5.4 公式） |
| 累计收益 | 总资产 − 净投入 |
| 当日盈亏 | Σ (最新价 − 前一日价) × 份额 |
| 持仓明细 | 每只基金的份额、成本、市值、占比、当日/浮动盈亏 |
| 收益曲线 | 按区间（1M/3M/6M/1Y/全部）展示累计收益走势，并与沪深300 基准对比；基准缺失时给说明而不是空白 |
| 近 7 日收益 | 每日盈亏柱状图（红涨绿跌） |
| 全球指数看板 | 主要指数最新点位与涨跌幅，按市场分组切换（不是平铺） |
| 同步状态 | 各基金本地数据日期；滞后标红并可**一键重试**同步 |

### 9.2 同步状态怎么用
- 数据滞后（超过应有的最新交易日）时该行标红：通常是上游接口抖动，点重试即可；连续失败看后台日志。
- 手动同步与每日定时任务**用同一把分布式锁**，不会互相打断或重复写。

## 10. 平台配置

### 10.1 AI 模型配置：厂商、Base URL、Token
位置：侧栏【平台配置】→【AI 模型配置】卡片。
- **厂商**：智谱 / 千问 / DeepSeek / Kimi / MiniMax（都是 OpenAI 兼容端点，换个厂商只是换个地址与 Key）。
- **Base URL**：切换厂商会自动填入该厂商默认地址；用自建/代理地址可直接改。
- **Token**：按厂商签发，**每个厂商各存一份**。已配置过时输入框显示"已配置（****后四位），留空不改"——你切换厂商或改单价时**不用重填 Token**。

### 10.2 模型怎么选
- 点【拉取模型列表】会调该厂商的 `/models` 接口，列出可用模型，并对内置已知的**免费档**标注"（免费）"；厂商不提供该接口时可直接手工输入模型名。
- 免费档模型（如智谱的 glm-4-flash）指令遵循能力弱一些，边界问题上表现不如付费档；追求稳定可换付费模型。
- 选好模型后点【保存并生效】，**立即生效，无需重启应用**。

### 10.3 单价怎么填（决定了"AI用量统计"里的钱准不准）
- 三个单价都是**元 / 百万 token**，按厂商官网当前价填，**按厂商各存一份**（切厂商自动用那一家的价）。
- **输入单价**：普通输入 token 的价；**缓存单价**：命中提示缓存的输入 token 的价（多数厂商明显便宜，DeepSeek 尤其便宜）；**输出单价**：生成 token 的价。
- 缓存单价留 0 时按输入单价计（不会漏算）；**免费模型三个都填 0**（费用恒为 0）。
- 单价是**快照**：改价只影响之后产生的流水，历史费用不会被改写。

### 10.4 连通性自检
点【连通性自检】用当前表单里的地址/Token/模型发一句最小请求，几秒内返回"连通正常（模型已响应，耗时 x ms）"。自检不修改配置，但**会真实消耗 token**并记一行"自检"用量。

### 10.5 切换厂商：选中 + 保存才切换（且不覆盖别家）
- **每个厂商的配置各存一份**：Base URL、模型、Token、三个单价互不覆盖。切到旧厂商，它的配置还在，Token 也不用重填。
- 「当前使用」= 对话实际调用的那家。下拉里会标出「当前使用」与「已配置」。
- **选中某厂商只是把它的配置载入表单**；点【保存并生效】才会真正切过去（避免误点下拉把对话搞挂）。卡头会提示"当前使用：X（保存后才切换）"。
- 前提：切到的那家必须已配 Token（或本次填上），否则对话会提示"尚未配置模型"。

### 10.6 账号、通知邮箱与 SMTP
- 【基本信息】改昵称与**通知邮箱**（信号/告警邮件的收件人）。
- 【安全设置】改密码（改完需重新登录，会全端下线）；连续 5 次密码错误会锁定 10 分钟，会话有效期 7 天。
- 【邮件通知】卡片可**直接编辑并保存**：SMTP 服务器、端口、通知开关、发件账号、授权码、发件人、收件人。
  配置存在**本平台数据库**里，点【保存邮件配置】**立即生效、无需重启应用**（授权码也不再写在配置文件或环境变量里）。
- **打码值 = 沿用原值**：发件账号与授权码回显为 `83***@qq.com` 这类打码值时，表示"已存着这份配置"，
  **不改动直接保存就是保持原值**，不会把打码值写进去；要换账号或授权码时把整段重新填一遍即可。
- **收件人留空**则用上面资料里的通知邮箱；两者都没有时发送会提示先补一个。
- 【发送测试邮件】与【通知开关】相互独立：**开关关掉后仍可手动发测试邮件**（便于先验证参数再开自动发送）。
- 常见失败原因：端口填错（QQ 邮箱 SSL 用 465、STARTTLS 用 587）、把**登录密码当授权码**填了（要去邮箱后台生成授权码）、
  授权码过期，或短时间内连发多封被上游临时限流（稍后重试即可，界面会给出中文原因）。

## 11. AI 助手与用量

### 11.1 怎么问、能问什么
- 打开方式：右下角圆形按钮（可拖动）；面板顶部有"历史会话/新会话/收起"，面板本身也能拖动与缩放。
- **能问**：持仓与盈亏、某只基金的行情/档案/估值、历史走势、策略信号、全球指数、**以及本平台怎么用**（功能、参数、配置、报错）。
- **会解释边界**：具体政策/新闻/宏观事件、具体个股数据——它会说明"没有这类数据源、不猜"，并给你 2 个可替代的问法；创作类、闲聊、角色扮演、套取提示词会被一句统一话术拒答。
- **可以讲方法**：PE/ROE/股息率/估值分位怎么看这类通用方法能讲，但不掺具体数字、不对个股下结论。

### 11.2 会话与记忆
- 每个会话有独立上下文（记忆窗口 **20 条**消息），超出后最早的会被截断，但**MySQL 里保留全量历史**，可随时回看。
- 会话 ID 存在浏览器本地，刷新页面仍能接着问；【历史会话】可切换/删除；换会话或点【新会话】可以开一个干净上下文。
- 单次提问上限 2000 字；流式回答默认 60 秒超时保护；回答流式打字机输出，Markdown 表格/代码块会正常渲染。

### 11.3 用量与费用怎么算（【AI用量统计】页）
- **一次咨询记一行**流水；一次咨询里如果调用了工具（查行情/持仓等），会产生**多轮**上游请求，token 是各轮之和（页面会显示"对话 · N 轮"）。
- 费用 = 未命中缓存输入 × 输入单价 + 命中缓存输入 × 缓存单价 + 输出 × 输出单价（÷100 万）。
- 工具调用的多轮**每次都要重发**系统提示词与工具说明，所以输入 token 会比输出大得多，这是正常的。
- 用途分三类：**对话**（真正计费）、**自检**（连通性自检也真实花钱）、**护栏**（被护栏拦下的提问，0 费用）。
- 明细里的「估算」标记：极少数情况下上游没回使用量，平台按字符估算并**明确标注**，不假装精确。

### 11.4 每日额度（超限会怎样）
- 额度是**全局一份**（不跟厂商走，切厂商不会改它）：**token 上限**、**费用上限**、**预警百分比**三项，在【AI用量统计】页维护；填 0 表示不限制。
- 口径是**自然日**（00:00 重置，自动生效，无需等待任务）。
- 用量达到**预警线**：浮窗用量条变黄提醒，仍可正常使用。
- 用量**达到上限**：新的提问会被**直接拒绝**（浮窗输入框禁用并显示原因），且**不会调用上游、不产生费用**；明日 00:00 自动恢复。默认额度：30 万 token/日 + ¥3/日 + 80% 预警。
- 费用额度要生效，前提是**当前厂商的单价填了**（未填时费用恒为 0，页面会提示"按费用的限额不生效"）。

## 12. 数据同步与定时任务

### 12.1 每天几点在做什么（时间表）
| 时间 | 任务 | 说明 |
| --- | --- | --- |
| 15:30（交易日） | ETF 日线同步 | **全量覆盖**当日/近 10 年前复权日 K（见 12.3） |
| 20:00（交易日） | 场外净值同步 | 未出净值的记入待补拉 |
| 次日 07:00 | 净值补拉 | 补前一天没取到的场外净值 |
| 20:30（交易日） | 指数估值同步 | 更新跟踪指数 PE 序列 |
| 21:00（交易日） | 策略信号 + 邮件 | 全部启用策略算当日信号，有买卖信号则发邮件 |
| 每 5 分钟（9-23 点） | 行情缓存刷新 | 供页面/看板读取最新报价 |
| 17:00（交易日） | 非持仓自选基金同步 | 增量补齐 |
| 交易时段每 10 分钟 | 持仓基金同步 | 9:30-11:30 / 13:00-15:00 内自判执行 |
| 22:00 | 同步汇总 | 汇总当日同步结果 |
| 22:05 | 异常告警 | 只对**滞后**的基金发告警邮件 |

### 12.2 数据滞后怎么看、手动同步怎么做
- 看【仪表盘 → 同步状态】或【基金池 → 最后同步】列；滞后行会标红，点重试即触发一次同步。
- 手动同步是**增量**（从本地最新日期+1 拉到今天）；历史数据有洞时用【数据导入】重导（覆盖刷新）。
- 盘中手动同步能拿到当日实时数据，次日收盘任务会用官方收盘数据覆盖修正。

### 12.3 为什么 ETF 每天要全量重拉（前复权口径）
前复权价以"最新价格"为基准，**每次分红除权后，全部历史前复权价都会整体变化**。如果只做增量追加，历史段会停留在旧口径，曲线与指标就会出现"断层"。
所以平台的选择是：**每日全量覆盖**（一只基金一次请求、约 2400 行写入），简单且绝对正确；盘中手动同步仍用增量，次日全量任务自动纠正口径。

## 13. 常见问题 FAQ

### 13.1 数据类
- **某只基金查不到行情**：先确认它在不在自选池（AI 只会查自选池内的基金）；不在就【数据导入】导入。
- **数据日期很旧/没更新**：看仪表盘同步状态是否标红；点重试；仍不更新就是上游接口抖动，稍后再试（日志关键词"同步失败"）。
- **股息率列是 `--`**：该基金没有分红记录，或未复权价格数据还没补齐（每日全量同步会补上）。
- **估值百分位是 `--`**：跟踪指数未识别，或指数估值历史不足（少于 30 个采样点不给百分位）。

### 13.2 记账类
- **持仓和券商对不上**：核对流水金额是否按对账单填（价格是派生的，改金额比改价格准）；确认没有漏记分红。
- **现金余额是负的 / 转不出去**：现金 = 转入−转出−净投入，为负通常意味着少了一笔"转入"（把外部资金补记成一笔转入即可）。已知口径限制见 3.4 节末。
- **分红记完成本变了**：这是设计如此——现金分红会冲减持仓成本并计入已实现盈亏。
- **想把红利再投资**：拆成"分红 + 买入"两笔（见 5.3）。

### 13.3 AI 类
- **提示"尚未配置模型"**：到【平台配置 → AI 模型配置】选厂商、填 Token、拉取并选择模型，保存即生效。
- **提示"今日 AI 用量已达上限"**：到【AI用量统计】页看用量与额度，调高上限（或明日 00:00 自动恢复）；注意超限时**不会调用上游**，所以不会偷偷花钱。
- **提示"AI 服务暂时不可用（原因）"**：多为上游接口异常或超时；可先用【连通性自检】确认 Key/地址/模型是否正常，再重试。
- **回答里的数字**：凡是价格、持仓、盈亏、信号这类数字都来自工具实时取数；如果它说"查不到"，通常就是自选池里没有这只基金或数据未同步。
- **不想让它乱花 token**：把每日 token/费用额度设小（如 5 万 token/日），超限自动拒绝。

### 13.4 运维类
- **启动/停止**：仓库根目录 `sh build.sh`（会先停应用再打包，避免 jar 被占用）与 `sh stop-app.sh`；启动 `java -jar quant-web/target/quant-web-1.0.0.jar`。默认端口 **8080**。
- **依赖**：MySQL（库名 `quant`，开发环境 root/root）、Redis（会话与记忆窗口）；表结构由 `schema.sql` 在启动时**幂等**创建/迁移，升级只需替换 jar 重启。
- **首次启动账号**：`admin` / `admin123`（来自 `quant.init.admin-username/password`），请登录后立即改密码。
- **备份**：`deploy/mysql-backup.sh` 做数据库备份；`docs/` 是研发文档，与运行数据无关。
- **日志**：应用日志在 `logs/`（含按天滚动与错误单独文件）；接口调用日志会打 traceId，便于串联排查。

## 14. 术语与口径速查

### 14.1 价格类
| 术语 | 含义 |
| --- | --- |
| 单位净值 | 场外基金每份的净值（未复权） |
| 复权净值 | 把分红再投资后的累计净值，用于算收益/回测（本平台场外用它撮合） |
| 前复权价 | 以**最新价**为基准回溯调整过的历史价格；**最新一日就是真实成交价**，历史段被压低（分红越多越低） |
| 未复权价 | 当日真实成交价；历史股息率的分母必须用它 |

### 14.2 收益类
| 术语 | 含义 |
| --- | --- |
| 净投入 | 真正投进持仓的钱：Σ买入(含费) − Σ卖出净额 − Σ分红净额 |
| 现金余额 | (Σ转入 − Σ转出) − 净投入 |
| 总资产 | 持仓市值 + 现金余额 |
| 累计收益 | 总资产 − 净投入（排除外部转入转出的真实盈亏） |
| 摊薄成本价 | 剩余持仓成本 ÷ 持有份额（买入含手续费，卖出按它结转） |
| 已实现盈亏 | 卖出/分红已经落袋的盈亏 |
| 浮动盈亏 | (最新价 − 成本价) × 份额，尚未落袋 |

### 14.3 估值与分红类
| 术语 | 含义 |
| --- | --- |
| PE 百分位 | 当前 PE 在近 N 年历史中的分位（越低越便宜）；分档加/减仓策略的依据 |
| 股息率（TTM） | 过去 12 个月每份分红合计 ÷ 当日真实价格 |
| 单次分红股息率 | 某一次分红 ÷ 除息日真实价格 |
| 溢价率 | 仅 ETF：(收盘价 − 当日净值) / 净值；正数表示场内买贵了 |
| 最大回撤 | 从峰值到谷底的最大跌幅（同时记录峰、谷、修复日） |
| 夏普比率 | 单位波动换来的超额收益（无风险利率默认 2%） |
